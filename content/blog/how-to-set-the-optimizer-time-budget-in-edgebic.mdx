**To set the optimizer time budget in EDGEBIC, open the Optimizer tab in the Schedule area, pick a Goal, and choose a Time budget of 10, 30, or 60 seconds before you click Run.** The optimizer in EDGEBIC by User Solutions spends up to that long trying complete alternative schedules and shows the best one next to your current plan; the budget is a per-run choice, the default is 30 seconds, and a longer budget only ever helps because the result is guaranteed never worse than what you had and nothing is saved until you Accept.

This post covers the time budget. To choose which engine powers the run, see [how to choose the optimizer engine in EDGEBIC](/blog/how-to-choose-the-optimizer-engine-in-edgebic); the full task library is at the [EDGEBIC how-to hub](/blog/edgebic-how-to-hub).

## Before You Start

- You have open, scheduled manufacturing orders. The optimizer improves an existing plan.
- You can reach the **Optimizer** tab in the Schedule area, or the **Optimize Schedule** button on the Drive Schedule toolbar.
- You know the run is safe to try: nothing changes until you press Accept.

## The Steps

1. **Open the Optimizer tab.** In the **Schedule** area, open the **Optimizer** tab, or click **Optimize Schedule** on the **Drive Schedule** toolbar, which switches you there.
2. **Read the contract.** The line at the top confirms the promise: it tries many schedules and shows the best one, and nothing changes until you press Accept.
3. **Pick a goal.** Choose a **Goal**, for example On-time first, from the dropdown.
4. **Choose the time budget.** In **Time budget**, select **10**, **30**, or **60** seconds. The default is 30. Longer budgets let the optimizer try more alternatives.
5. **Run.** Click **Run**. The status shows it is trying schedules; **Cancel** stops it harmlessly with nothing changed.
6. **Read the result.** When it finishes, the verdict, a badge reporting how many schedules were tried, a KPI comparison, and the list of moves appear. Nothing is saved yet.
7. **Accept or Discard.** Press **Accept** to save the proposal through the normal scheduling pipeline, or **Discard** to keep your current plan untouched.

## What Changes When You Save

| Surface | Effect |
|---|---|
| While the run thinks | Nothing. Jobs, capacity, and everyone else's view stay exactly as they are. |
| A longer budget | More complete alternative schedules tried, so a better plan is more likely to be found. |
| The proposal | Lives on your screen only until you Accept. |
| On Accept | The proposed starts and ends replace the current ones for the moved operations; an audit record is written. |
| On Discard | Nothing. The database is byte-for-byte untouched. |

## How to Check It Worked

After a run, read the badge in the result area. It reports how many complete schedules were tried and in how long, for example "Best of 6 schedules tried in 2.1s." Raise the **Time budget** and run again on the same workload; on a nontrivial plan the badge should report more schedules tried, and the verdict may improve. Because nothing saves until Accept, you can compare a 10-second run and a 60-second run freely and keep whichever plan you prefer.

## Common Mistakes

**Assuming a longer budget can hurt.** It cannot. Every proposal is compared against your current plan and shown only if it is strictly better, so more thinking time only ever finds a better plan or confirms your current one.

**Looking for the time budget in Settings.** It is not there. The budget and the goal are per-run choices on the Optimizer tab; Settings only stores which engine runs.

**Worrying the run locks the plan.** It does not. A run computes in memory and holds the result on your screen until you Accept.

**Accepting without reading the moves.** The move list is deliberately short, showing only operations that move. Read it before you Accept so you know what the plan changes.
