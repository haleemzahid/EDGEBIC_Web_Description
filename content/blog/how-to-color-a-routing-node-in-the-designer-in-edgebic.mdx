**To color a routing node in the EDGEBIC by User Solutions designer, select the node on the canvas and set its fill color, border color, and text color in the properties panel, then save the routing.** The styling is stored on the step, so the diagram reopens looking the way you left it. Nothing about the schedule changes, because color is presentation only.

Diagrams get read by people in a hurry. Color is how you make an outside processing step, an inspection gate, or a bottleneck machine obvious in a drawing with a dozen boxes on it. Used with restraint it makes a routing self-explaining. Used without restraint it makes a routing look like a fruit bowl.

## Before You Start

- **The routing exists with its steps connected.** Styling is a finishing pass.
- **Decide the meaning before the palette.** One color, one meaning, written down somewhere. Colors that mean different things on different routings are worse than no color at all.
- **Know which drawing you are styling.** The product's standard routing and a scheduled job's own copy are different drawings, and resetting a job's copy back to the standard cannot be undone.
- **Keep contrast in mind.** Text color and fill color have to work together, because a node nobody can read is not an improvement.

## Step 1: Open the Designer

Open the **BOR** tab, select the routing, and click **Designer** on the toolbar. The canvas shows the routing as nodes and connectors, with the toolbox on the left and the properties panel on the right.

## Step 2: Select the Node

Click the node you want to style. The properties panel fills with that node's editable fields. Nothing selected shows a prompt to select a node instead.

The panel carries the numbers that matter to the scheduler, setup time, hours required, queue time and the rest, plus a styling group at the bottom.

## Step 3: Set the Colors

In the styling group, set:

| Field | What it changes |
|---|---|
| **Fill Color** | The body of the node |
| **Border Color** | The outline |
| **Text Color** | The step name shown on the node |

Change the fill first, then check the text is still readable against it. A dark fill with dark text is the usual mistake, and it is invisible until somebody opens the diagram on a projector in a production meeting.

## Step 4: Set the Node Icon If It Helps

The same group carries a **Node Icon** setting. An icon reinforces a category faster than color alone for readers who are scanning rather than studying, and it survives being printed in black and white, which color does not.

Use it sparingly and for the same reason you use color: to mark a class of step, not to decorate an individual one.

## Step 5: Repeat Only Where It Earns Its Place

Style the nodes that carry a message and leave the rest at their default. A routing where three nodes are colored says something. A routing where every node is colored says nothing, because there is no contrast left to read.

Good candidates on most routings:

- **Outside processing**, where the part leaves the building.
- **Inspection or gate steps**, where the routing can stop.
- **The bottleneck machine**, so the constraint is visible in every drawing that touches it.

## Step 6: Save

Click **Update** on the toolbar. This saves the routing, and node styling goes with it.

Skip the save and the colors are discarded when you leave the designer, which is the single most common reason styling appears not to stick.

## How to Check It Worked

1. **Close and reopen the designer.** The colors should return exactly as set. This is the real proof.
2. **Read the node names.** Every node should be legible at fit to window magnification, not only zoomed in.
3. **Check the Gantt is unaffected.** Open the schedule: the work center's bar colors are unchanged, because those are a separate setting.
4. **Show it to somebody who did not do it.** If they can tell you what the colored nodes have in common without being told, the scheme works.

## Common Mistakes

**Confusing node color with work center color.** Changing a node's fill does not change the machine's bars on the Gantt, and changing a work center's colors does not restyle any routing node. If it is the schedule you want to recolor, [how to name and color a work center for the Gantt in EDGEBIC](/blog/how-to-name-and-color-a-work-center-for-the-gantt-in-edgebic) is the right screen.

**Coloring by machine rather than by meaning.** Machines are already identifiable by name. Color earns its place when it says something the name does not.

**Styling a job's own routing copy when you meant the standard.** The copy belongs to one job and can be replaced wholesale by a reset. Style the standard routing if you want every future job to inherit the look.

**Building a palette nobody documents.** Six colors with six meanings and no key is noise. Write the scheme down and keep it to three.

**Forgetting to save.** Colors are part of the routing save, not an instant setting.
