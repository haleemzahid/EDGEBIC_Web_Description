**To create a watched-file integration in EDGEBIC by User Solutions, open the Integration tab, click New Integration, leave Source on File (watched), set the File path to the file your ERP drops, choose the Target entity and its Import Mask, then Save.** This is the common case: another system writes a file to a share on a schedule of its own, and EDGEBIC picks it up without anyone clicking anything.

An integration does not replace an import mask. It runs one. Everything about how your columns map to EDGEBIC fields is already decided by the mask, and the integration only supplies the trigger.

## Before You Start

| Prerequisite | Why |
|---|---|
| An import mask already exists for this data | An integration runs a mask, it does not define one. You can create the mask from inside the form, but there has to be one |
| You know the exact path the file lands at | The watcher is built against that path, and a guess produces an integration that never fires |
| The folder holding the file exists | The watcher is built against the folder. A folder missing when the host starts means no watching for that integration |
| Access to the Integration tab | The tab is permission-controlled. If you cannot see it, ask your administrator |

## Step 1: Open the Integration Tab and Start a New Definition

Open the **Integration** tab from the main navigation, then click **+ New Integration** in the header strip. An empty **Configuration** form opens on the right, and the footer tells you plainly that this is a new integration to fill in and save.

## Step 2: Name It After the Routine, Not the File

Type a **Name**. Name it for the job it does, not for the file it happens to read right now, because file names change and routines do not. `ERP Products - nightly sync` survives a rename of the export; `products.csv` does not.

## Step 3: Leave Source on File (watched) and Fill In the File Details

**Source** offers **File (watched)** and **External SQL Server**. Leave it on the first.

| Field | Required | What it does |
|---|---|---|
| **File path** | Yes | The exact file EDGEBIC watches and imports. Type it or click **Browse...** |
| **Sheet** | Only for Excel | Which worksheet to read. Appears only when the path ends in an Excel extension |
| **Import automatically when the file changes** | No | On: a new or changed file triggers a run by itself |
| **Debounce (s)** | No | How long the file must sit quiet before the run starts, from 1 to 300 seconds |

**Browse...** does not require the file to exist yet, so you can point at tomorrow's drop today.

## Step 4: Pick the Target Entity and the Mask

In the **Import Mask** section, pick the **Target entity** first, then the **Mask** beside it. Only masks belonging to that entity are offered, which is a guard rather than a limitation: it makes it impossible to point a product mask at a sales-order feed.

If no mask exists yet, click **New...**. For a file source EDGEBIC reads the file's heading row first and opens the mask editor with those columns already loaded, so you only drag them onto the fields.

## Step 5: Set the Schedule and the Safety Limits

The right-hand **Schedule and Limits** panel carries three controls. Tick **Run every** and set the minutes if you want an interval on top of the file trigger. Leave the two safety limits at their defaults unless you have a reason: **Max rows/run** defaults to unlimited, and **Max minutes/run** defaults to a wall-clock cap that stops a run still going at that point.

Hitting the row cap ends the run as CompletedWithErrors, never as a success, and the rows past the cap are simply not read. Hitting the time cap ends the run as Failed, and rows already written before the cut stay written.

## Step 6: Save

Click **Save**. The card appears in the left rail immediately with its schedule summary and, once enabled and scheduled, a countdown chip. Saving the form saves the definition only. Nothing is imported at that moment.

## How to Check It Worked

Click **Run Now** on the card rather than waiting for the first natural trigger, then open the **Run History** tab. One row should appear with its trigger, its counts of created, updated, reused, skipped and failed rows, its duration and any message. A run that succeeded with sensible counts is your proof that the path, the mask and the permissions all line up.

Then check the data itself. The records the mask's target entity covers should have changed by exactly the same rules a manual import follows.

## Common Mistakes

**Expecting the schedule to update.** A run changes data, not the plan. Jobs already scheduled carry their own frozen routing snapshot and are unchanged. Run the scheduler afterward if you want the new data reflected in dates. See [how to run the scheduler](/blog/how-to-run-the-scheduler-in-edgebic).

**Debounce left at zero on a large export.** The bigger the file, the longer the writer holds it open, and the more likely a zero-debounce watcher reads a partial file.

**Pointing at a mapped drive the host cannot see.** The watcher is built by whatever account runs the host, not by your desktop session. A path that works in your Explorer window is not evidence.

**Assuming a silent integration is a failed one.** Silence usually means it never triggered. [Checking whether anything is actually hosting your syncs](/blog/how-to-tell-whether-anything-is-actually-hosting-your-syncs) separates the two cases.
