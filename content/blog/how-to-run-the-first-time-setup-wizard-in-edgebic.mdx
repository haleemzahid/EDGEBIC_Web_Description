**To run the First Time Setup Wizard in EDGEBIC, launch the application on a fresh database, create the administrator, sign in, and the wizard opens on its own; then work through six steps in order, Data Source, Shifts, Products, Work Centers, BOR, and Orders, and finish to restart into a plant that can schedule its first job.** The wizard in EDGEBIC by User Solutions walks you through the minimum data a finite capacity scheduler needs, in the sequence where each step depends on the ones before it, so a new site goes from an empty database to a real schedulable order without guessing what to enter first.

This post covers the wizard itself. For the install and the administrator account that come before it, see [how to install and connect EDGEBIC](/blog/how-to-install-and-connect-edgebic); the full task library is at the [EDGEBIC how-to hub](/blog/edgebic-how-to-hub).

## Before You Start

- EDGEBIC is installed and you have launched it against a new, empty database.
- You have created the administrator account and signed in. The wizard opens after the first sign-in.
- You know the basics of your plant: at least one shift, one product, three work centers, and one job you want to schedule.

## The Steps

1. **Read the welcome line.** The wizard opens on "Welcome to EDGEBIC Setup Wizard" with a step indicator column down the side: Data Source, Shifts, Products, Work Centers, BOR, Orders.
2. **Step 1, Configure Data Source.** Accept the default local database (nothing to do) or point EDGEBIC at SQL Server using the same editor described in [how to connect EDGEBIC to SQL Server](/blog/how-to-connect-edgebic-to-sql-server). Click **Next**.
3. **Step 2, Create Your First Shift.** Define working hours, for example a Day Shift running 08:00 to 16:00. This is the working time every later step schedules into.
4. **Step 3, Add Your First Product.** Enter one product, for example Widget-A.
5. **Step 4, Create Work Centers.** The wizard asks for at least three, for example Saw-1, CNC-Mill-1, and Assembly-1.
6. **Step 5, Create Bill of Resources (BOR).** Build a simple routing for the product, the ordered manufacturing steps across those work centers.
7. **Step 6, Create Your First Manufacturing Order.** Enter a job for the product. On this step the Next button reads **Complete Setup**.
8. **Handle each Step Complete overlay.** After steps 2 through 6 an overlay asks whether to continue. Click **Yes, Next Step** to advance, or **No, Add Another** to stay on the step and add more records of the same kind.
9. **Finish.** On the "Setup Complete!" page click **Finish, Start EDGEBIC**. The application restarts into the main window on the Dashboard tab, ready to schedule.

## What Changes When You Save

| Surface | Effect |
|---|---|
| The database | Populated with your first shift, product, work centers, routing, and order, in dependency order. |
| The main window | On restart it opens on the Dashboard, and the Schedule area now has a job to plan. |
| The Data Source choice | Whatever you confirmed on step one becomes the active connection; a local file stays local until you switch. |
| Later editing | Every wizard step maps to a normal tab, so you keep editing the same records under Daily Hours, Product, Workcenter, BOR, and Schedule. |

## How to Check It Worked

After the restart, open the **Schedule** tab and its **Drive Schedule** sub-tab. Your first order should be listed. Run the first schedule and open **Job View** to confirm the operations landed on real machine time across your three work centers. If the order schedules cleanly, the wizard did its job: shifts, product, work centers, and routing all reference each other correctly.

## Common Mistakes

**Skipping the shift.** Nothing schedules without working time. If you rush past the Shifts step with no real hours defined, later steps have no capacity to place work into, and the first schedule run produces nothing.

**Entering fewer than three work centers.** The wizard asks for three on purpose, so a routing has somewhere to go. A single-work-center routing is a poor first plant to learn on.

**Treating a closed wizard as a dead end.** Closing the wizard loses nothing. Every step is the ordinary editor for its tab, so you can create the same records later in the same order: shifts, products, work centers, routing, orders.

**Expecting a data-source switch to migrate data.** Accepting the local database now and switching to SQL Server later gives you an empty shared database, not a copy of what you built. Plan the data move as a separate step when you migrate.
