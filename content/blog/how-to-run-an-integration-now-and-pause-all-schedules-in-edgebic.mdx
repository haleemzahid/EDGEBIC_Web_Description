**To run an integration immediately in EDGEBIC by User Solutions, select it in the left rail and click Run Now in the detail action bar, or click the play button on its card.** To stop everything from firing on its own, tick **Pause all schedules** in the header strip. These are the two controls you reach for most, and they solve opposite problems: one forces work to happen now, the other stops work happening while you are busy.

## Before You Start

| Prerequisite | Why |
|---|---|
| At least one integration is defined | These controls act on definitions, not on masks |
| You know whether you want a temporary or a persistent stop | Pause all schedules is session-only. A card's toggle is persistent |
| Access to the Integration tab | The tab is permission-controlled |
| You know a run changes data, not the plan | An integration never recalculates the schedule. That is a separate step |

## Step 1: Run One Now

Select the integration in the left rail and click **Run Now** in the detail action bar, or use the play button on the card. Three things change at once: the card swaps to a progress bar, the chip starts counting rows as they are read, and the **Live Log** tab narrates the run while it is happening.

While a run is in progress, **Run Now** is replaced by **Cancel Run** in the same position. That is deliberate. The control that started the run is the control that stops it, so you are never hunting for a way out of a run you regret.

## Step 2: Cancel a Run in Progress

Click **Cancel Run**. Rows already written stay written, which is worth saying out loud because people expect a cancel to roll back. It does not. A canceled run is recorded in **Run History** with its own status, so the record shows plainly that the run was stopped rather than that it failed on its own.

## Step 3: Disable a Single Integration

Use the toggle switch on the right of its card. This stops both its schedule and its file watching, and the chip reads **Disabled**. The state belongs to the definition, so it survives a restart. Use this when one feed is wrong and the rest of the plant's syncs should carry on.

## Step 4: Pause Everything for the Session

Tick **Pause all schedules** in the header strip. All scheduled runs and all file watching stop. **Run Now** still works, which is the useful part: you can keep pulling data deliberately while nothing fires behind your back.

This lasts for the current session only. Restarting clears it. That is a feature rather than an oversight, because the worst outcome for a temporary pause is that it quietly becomes permanent.

## Step 5: Delete One, and Keep Its History

Click **Delete** in the action bar or the delete button on the card, and confirm. Its run history is kept for audit and stays visible under **Run History** when you tick **All integrations (includes deleted)**.

## How to Check It Worked

Open **Run History** and read the newest row. The **Trigger** column tells you which mechanism started it: **Manual** when you clicked Run Now, **Schedule** for the interval, **FileWatch** when the file changed, or **Simulator**. If you expected a manual run and see a scheduled one, or the reverse, you have learned something useful before it matters.

For a pause, the check is the absence of new rows plus the presence of a working **Run Now**. If Run Now is also dead, the problem is the host, not the pause. See [checking whether anything is actually hosting your syncs](/blog/how-to-tell-whether-anything-is-actually-hosting-your-syncs).

## Common Mistakes

**Expecting the plan to move after a run.** Runs change data, not the schedule. Jobs already scheduled carry their own frozen routing snapshot and are untouched. Run the scheduler yourself afterward.

**Treating Pause all schedules as a persistent setting.** It clears on restart. For a change window that spans a restart, disable the individual cards instead.

**Clicking Run Now repeatedly when nothing appears to happen.** A second trigger for a running integration is refused, not queued. The header tells you it is already running.

**Deleting a noisy integration to silence it.** Disabling it with the toggle keeps the definition and the option to bring it back. Deleting keeps only the history.
