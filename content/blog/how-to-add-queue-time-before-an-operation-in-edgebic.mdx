**To add queue time before an operation in EDGEBIC by User Solutions, set Queue Time on the routing step that runs immediately before it.** The control lives on the routing (Bill of Routing) step whose completion begins the wait, not on the operation that is waiting. Once you save and reschedule, the next operation cannot start until the queue hours have elapsed, and those hours are counted only during active working shifts. Queue time reserves no machine capacity, so it is the right tool for a real wait such as cooling, curing, drip time, or an inspection buffer.

This recipe covers one specific task. For how queue sits alongside flow and transit in the timing pipeline, read [how EDGEBIC composes step timing](/blog/how-edgebic-composes-step-timing) and the concept overview [EDGEBIC queue and transit times explained](/blog/edgebic-queue-and-transit-times-explained). To set all three buffers together, see the broader recipe [how to set queue, flow, and transit times](/blog/how-to-set-queue-flow-and-transit-times-in-edgebic).

## Before You Start

- The routing open, with the step that precedes the operation you want to delay identified. That upstream step is where the queue value goes.
- The wait length in hours, and confirmation it is a genuine wait (cooling, curing, inspection) rather than machine work, which belongs in the step's hours instead.
- Confirmation the same step does not carry a flow step or transfer batch, since a lot-streaming gate on the step discards the queue.

## Step by Step

1. Open the **BOR** tab and select the routing.
2. In the grid, find the step whose completion starts the wait (for example, the welding step before grinding).
3. In that row, set **Queue Time (hrs)** to the buffer you need, for example `2`. In the Designer, the same field appears as **Queue Time (hours)** in the node's Properties panel.
4. Leave the **Flow Step (hrs)** and **Transfer Batch** fields on that step at 0.
5. Click **Update Standard BOR**.
6. Run **Generate Schedule** (Drive Schedule) so the plan picks up the new buffer.

## What Changes When You Save

On the next scheduling run, EDGEBIC walks the work center's shift calendar forward from the step's end and consumes the queue hours only inside active shifts. Nights, weekends, and holidays do not count. The result becomes the earliest start for the next step. A four-hour queue that begins at 14:30 on an 08:00 to 16:00 shift uses 1.5 hours that day and 2.5 hours after the shift reopens the following working day, so the downstream operation lands at 10:30. The machine that just finished is free to run other jobs during the queue, because queue time books no capacity of its own. Every step after the queued one shifts out by the buffer, and the job's finish date reflects the wait.

## How to Check It Worked

Open the Job View and compare the queued step's end time with the next step's start time. The gap should equal the queue you set, measured only in working hours. If the queue crosses an overnight or a weekend, the calendar gap will be longer than the queue value, which is correct. If the gap is zero or wrong, confirm the queue is on the upstream step and that no flow step or transfer batch is set on the same row.

## Common Mistakes

- **Putting the queue on the waiting step.** Queue time delays the successor, so it lives on the step whose completion starts the wait. Placing it on the downstream operation buffers that operation's own successor instead, which is not what you intended.
- **Using queue time to model machine work.** Queue time reserves no capacity. If the delay is actually an operation (a bake, a cure that occupies an oven), model it as a step with hours so the work center is reserved. Use queue only for a true idle wait.
- **Combining queue with a flow step on one step.** A lot-streaming gate replaces the queue-adjusted end, so the queue is silently discarded. The Scheduler Anomalies report surfaces this as check F2. Move the buffer to Transfer Delay or to the downstream step.
- **Expecting queue to tick overnight.** Queue is shift-aware by design. A queue that starts near the end of a shift finishes after the next shift opens, not at a fixed clock offset. This is intentional and matches physical waiting.
