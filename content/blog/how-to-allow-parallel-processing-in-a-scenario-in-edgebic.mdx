**To allow parallel processing in a scenario in EDGEBIC, open the quote's Scenarios view, tick Parallel Processing in the Production Settings group, set Max Parallel Centers, then click Save Changes and Run Simulation.** The routing's parallel paths run at once inside that scenario only. Nothing on the real schedule changes.

A scenario in EDGEBIC by User Solutions is a named what-if variant of a quote's simulation. The Parallel Processing setting is the lever for testing "what if we ran the parallel paths in this routing at the same time," and Max Parallel Centers caps how many machines share the work. Because it is confined to the scenario, you can weigh the lead-time gain against the cost of staffing more machines before committing.

## Before You Start

- **A quote exists and has been simulated once.** Scenarios are children of a quote, and the base simulation is your comparison baseline. See [how to create a what-if scenario](/blog/how-to-create-a-what-if-scenario-in-edgebic).
- **The routing has a parallel path.** The toggle uses parallel work center paths that already exist in the routing. See [how to make two operations run in parallel](/blog/how-to-make-two-operations-run-in-parallel-in-edgebic).
- **You keep a baseline scenario.** A Parallel-Processing-off scenario is what you compare the parallel run against.
- **You will staff it for real if adopted.** The scenario proves the idea; running the parallel path in production is a separate step.

## Step 1: Open the Scenario View

On the **Quote** tab, select the quote and click **Scenarios**. The What-If Scenario Analysis view opens. Select an existing scenario or click **Create New Scenario** and name it after the lever, for example `Parallel milling`.

## Step 2: Find the Production Settings Group

On the **Scenario Parameters** tab, locate the **Production Settings** group.

## Step 3: Tick Parallel Processing and Set the Cap

Tick **Parallel Processing**, then set **Max Parallel Centers**:

| Field | Default | Effect |
|---|---|---|
| **Parallel Processing** | Off | When on, parallel work center paths in the routing may be used at once |
| **Max Parallel Centers** | 2 | Caps how many machines may run concurrently |

Raise **Max Parallel Centers** to let more machines share the work when the routing supports it.

## Step 4: Save and Simulate

Click **Save Changes**, then **Run Simulation**. Read the **Simulation Results**: **Estimated Start Date**, **Estimated End Date**, **Lead Time**, **Total Hours**, and **Estimated Cost**. Each run overwrites this scenario's stored results, and nothing touches the shop plan.

## What Changes When You Save

| Action | What changes | What does NOT change |
|---|---|---|
| **Save Changes** | The scenario's stored parameters | The quote, the schedule, the real routing |
| **Run Simulation** | The scenario's stored dates, hours, and cost | The production schedule; no real capacity added |

## How to Check It Worked

1. Confirm **Parallel Processing** is ticked and **Max Parallel Centers** shows your cap.
2. Click **Run Simulation** and note the **Estimated End Date**.
3. Open the **Comparison Analysis** tab, tick this scenario and a Parallel-off baseline, and read the Lead Time chart. A working parallel path shows a shorter bar.
4. If nothing moves, open the routing in the BOR editor and confirm a genuine parallel path exists for the setting to use.

## Common Mistakes

**No parallel path in the routing.** The toggle only uses parallel paths that already exist. Add one in the routing first, or the setting has nothing to act on.

**Targeting a non-bottleneck.** Overlapping a step that is not the constraint rarely shortens the whole job.

**Setting the cap too low.** If Max Parallel Centers is 1, there is no concurrency to gain. Raise it to the number of machines you would actually staff.

**Forgetting to save before simulating.** Save Changes stores the settings, and Run Simulation applies them.
