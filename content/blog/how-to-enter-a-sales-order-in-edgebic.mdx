**Entering a sales order in EDGEBIC** starts with the order header: the parent record that a customer's line items hang from. In EDGEBIC by User Solutions you open the sales order management dialog, click New, give the order a unique reference number, optionally attach a customer, and save. The order is created in draft status, which means it holds your entry safely without yet driving any demand into the plan. This guide covers the header only. Adding the product lines that carry quantities and due dates is a separate task.

For the wider picture of how orders, lines, and job links fit together, read [how to enter and manage sales orders](/blog/how-to-enter-and-manage-sales-orders-in-edgebic). For what an order actually is inside the planning engine, see [sales orders explained](/blog/edgebic-sales-orders-explained). Everything below describes documented behavior of [EDGEBIC](/edgebic), and the full task library lives in the [how-to hub](/blog/edgebic-how-to-hub).

## Before You Start

- You need access to the Sales Orders area from the toolbar or main menu.
- Decide on a reference number, or plan to accept the system's suggested one.
- Have the customer name ready if you want to attach it now. You can also add a new customer inline while entering the order.

## Step 1: Open the Sales Order Management Dialog

Open Sales Orders from the toolbar or main menu. The sales order management dialog appears, listing every existing order in a grid. This is your home base for orders: the place you create, edit, and delete them, and the place you will return to whenever you need to find an order later. Click **New** to start a fresh order.

## Step 2: Enter a Reference Number

The new-order window opens. The **Reference Number** field is the one required entry. It accepts up to 100 characters and cannot be blank, because a blank reference is rejected at save.

Two ways to fill it:

1. **Type your own.** Use whatever convention your business already runs on, such as a customer purchase order number or an internal sequence.
2. **Accept the suggested number.** EDGEBIC can propose the next sequential reference for the current year, in the form `SO-2026-0042`. It finds the highest existing number and adds one. The suggestion is advisory, so you are free to overwrite it.

The reference number is how you and everyone else will find this order later, so make it something you will recognize. If you enter high volumes, the suggested number is worth using consistently: it keeps references distinct and orders sorted chronologically in the grid, which turns "find last Tuesday's order" from a scroll into a glance. The suggestion is computed by scanning existing orders, so on very large datasets treat it as a helpful prefill rather than an instant lookup.

## Step 3: Attach a Customer (Optional)

Select a **Customer** from the dropdown if you want the order tied to one now. If the customer does not exist yet, click the **+** button beside the dropdown to add a new customer inline without leaving the order.

Attaching a customer is optional at this stage. You can save the order without one and add it later by editing the header. Note that the uniqueness rule for reference numbers is scoped per customer, so the same reference can exist for two different customers, but never twice for one.

## Step 4: Save

Click **Save**. EDGEBIC checks that the reference number is unique for the chosen customer, then creates the order. If the reference collides, the save is rejected with a message naming the number already in use, and nothing is created until you resolve it.

## What Changes When You Save

A new sales order row appears in the management grid, carrying your reference number. Its status defaults to **Draft**. That single detail governs everything downstream: a draft order, and any lines you later add to it, contributes nothing to firm demand. The order is a container waiting to be filled and activated, not yet a signal to the plan.

Nothing reaches the master production schedule, no product's projected balance moves, and no job is created. All of that waits until you add lines and change the status to confirmed. The draft-first design is deliberate: it lets you assemble an order, review it, and correct it before it ever touches the plan, which is exactly the discipline a scheduling platform built over 35 years of manufacturing deployments is meant to enforce. For how a confirmed order then flows into planning, see [how sales orders drive demand](/blog/how-sales-orders-drive-demand-in-edgebic).

## How to Check It Worked

Look at the management grid. The new order should be listed with the reference number you entered and a status of Draft. If you attached a customer, confirm it reads correctly in the customer column. That is the whole verification for header entry: the row exists, the number is right, the customer is right. There is nothing to check on the planning side yet, because a draft order asks for nothing.

## Editing or Removing the Header Later

The management grid is not just for creation. Select any order and click **Edit** to change its reference number or customer. Editing the header leaves the order's lines untouched: their quantities and due dates are unchanged, and changing the customer does not re-bucket them. The uniqueness check still applies, so an edited reference number that collides for the new customer is rejected.

Removing an order is a different action with heavier consequences. Deleting a sales order soft-deletes it and cascades that soft-delete to every manufacturing order linked to it, so those jobs leave the scheduling queue too. That is deliberate but not lightly reversible, and it does not reverse any inventory movements the jobs already posted. For a delivered order you want to retire cleanly, closing the order is the lighter move: see [how to close a sales order](/blog/how-to-close-a-sales-order-in-edgebic).

## Common Mistakes

- **Expecting demand to appear immediately.** A draft order is inert by design. If you are checking a product's planning grid and see nothing, the order status is almost always the reason. Confirm the order to activate its lines.
- **Reusing a reference number for the same customer.** EDGEBIC rejects a duplicate with a message naming the number already in use. The uniqueness rule is per customer, and it ignores soft-deleted orders, so a deleted order's number can be reused.
- **Typing your own numbers when volume is high.** Hand-typed references collide and sort unpredictably. Accepting the suggested sequential number avoids both problems.
- **Treating the header as the whole order.** The header carries no quantities or dates. Until you add lines, the order asks for nothing. Adding lines is the next task.

## What Comes Next
