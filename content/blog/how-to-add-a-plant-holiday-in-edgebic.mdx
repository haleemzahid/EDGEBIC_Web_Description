**To add a plant-wide holiday in EDGEBIC, open the Daily Hours tab, select the inner Holiday tab, and click Add Holiday.** Enter a **Name** and a **Date**, leave **Closes the whole day** ticked, and save. Every work center on every shift now shows zero capacity for that date, and the next scheduling run flows every job around it.

A plant holiday is the bluntest calendar instrument available: it closes the whole plant. That makes it the right tool for national holidays and annual shutdowns, and the wrong tool for a single machine's maintenance day. This page covers the whole-day case. For the full calendar setup sequence, read [how to set up shifts and holidays in EDGEBIC by User Solutions](/blog/how-to-set-up-shifts-holidays-downtime-in-edgebic).

## Before You Start

- **You have the date.** For recurring holidays, the exact month and day matter and the year does not.
- **You know it closes everything.** A holiday affects every work center and every shift. Single-machine closures use a different tool ([how to block a machine for a maintenance day](/blog/how-to-block-a-machine-for-a-maintenance-day-in-edgebic)).
- **You know whether the closure is a whole day or part of one.** Part-day closures use the partial holiday route.
- **You can rerun the schedule.** Existing jobs stay put until you do.

## Step 1: Open the Plant Holidays Page

Open the **Daily Hours** tab from the main navigation, then select the inner **Holiday** tab. The **Plant Holidays** page opens with the subtitle "Plant-wide closures affecting all work centers and shifts."

The grid columns are **S.#**, **Name**, **Description**, **Date**, **Recurring**, **Scope**, **Window**, **Active**, and **Actions**. Scan the existing rows before adding: duplicate holiday records are common and harmless, but they clutter an audit.

## Step 2: Click Add Holiday

Click **Add Holiday**. The **Holiday** dialog opens.

## Step 3: Fill In the Fields

| Field | Required | What it does |
|---|---|---|
| **Name** | Yes | The name shown in the grid and used for audit. `Independence Day` |
| **Date** | Yes | The calendar day. For recurring holidays, only the month and day matter |
| **Recurring each year** | No | When ticked, the closure fires on the same month and day every year |
| **Closes the whole day** | No | Ticked closes the entire day for every work center. Untick to specify a window instead |
| **Description** | No | A free-text note. Use it: `National holiday`, `Annual shutdown day 3 of 5` |
| **Active** | No | Untick to keep the record but stop the scheduler honoring it |

For a whole-day closure, leave **Closes the whole day** ticked and ignore the time fields entirely.

## Step 4: Decide Whether It Recurs

Tick **Recurring each year** for fixed-date public holidays and fixed annual shutdown dates. One record then covers every future year, which is much safer than maintaining a row per year and discovering the gap in January.

Leave it unticked for anything that moves: a shutdown week tied to a particular weekday, a one-off closure, an inventory count day. Those need a fresh record each year, entered during an annual calendar review.

## Step 5: Save

Click **Save**. The holiday appears in the grid with **Scope** set to **Whole Day**.

## What Changes When You Save

| Surface | Effect |
|---|---|
| **Plant Holidays** grid | Updates immediately, showing **Scope** = **Whole Day** |
| Available capacity on that date | Drops to zero for **every** work center and **every** shift |
| Resource Calendar and capacity dashboards | Show the closed day when refreshed |
| Existing schedules and promised dates | **Unchanged.** Bars stay exactly where they are |
| Next **Drive Schedule** run | Skips the date entirely and flows every job around it |
| Quote simulations | Run through the same calendar, so quoted dates already account for the closure |

That last row matters more than it looks. Quotes and production schedules share one engine and one calendar, so a holiday you add today is reflected in tomorrow's promise dates without any separate quoting setup.

## How to Check It Worked

1. Find the new row on the **Plant Holidays** grid. Confirm **Date**, **Recurring**, **Scope** = **Whole Day**, and **Active** ticked.
2. Open the Resource Calendar and read any work center's total capacity on that date. It should be zero.
3. Run **Drive Schedule**.
4. Open the Gantt and confirm no allocation sits on the closed date. If one still does, see [job scheduled on a holiday](/blog/job-scheduled-on-a-holiday-edgebic) for the short list of causes.

## Common Mistakes

**Adding the holiday and not rerunning.** The plan on screen was computed against the old calendar. Until Drive Schedule runs, the Gantt happily shows production on a day the plant is closed, and it is not wrong: it is stale.

**A recurring holiday saved on the wrong month or day.** Only the month and day are used for recurrence, so a one-day typo repeats forever. Audit the recurring rows once a year.

**Using a plant holiday for one machine.** A holiday closes the whole plant. Blocking a single machine for a teardown or certification day is a per-day capacity override on that work center, which leaves the rest of the plant running.

**Forgetting next year's non-recurring holidays.** A missing record means the scheduler plans production through a closed plant and promises a date nobody can hit. Build the annual calendar review into December.
