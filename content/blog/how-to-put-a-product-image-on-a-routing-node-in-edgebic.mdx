**To put a product image on a routing node in EDGEBIC by User Solutions, upload the picture on the product record and the graphical BOR editor renders it on that product's node automatically.** The control lives on the product, not on the routing step: you attach a PNG or JPG through the image placeholder on the product record, and the designer reads the stored image path when it draws the product or end-product node. This makes a routing diagram instantly recognizable, since the finished good and any component products show their real thumbnails rather than generic icons.

This recipe covers one specific task: putting an image on a node. For the visual editor itself, read [EDGEBIC graphical BOR designer tour](/blog/edgebic-graphical-bor-designer-tour). For adding the component that becomes a product node, see [how to add a material step to a routing](/blog/how-to-add-a-material-step-to-a-routing-in-edgebic).

## Before You Start

- The product whose image you want to show identified. This is usually the end product or a component that appears as a product node in the routing.
- A small image file (PNG or JPG), ideally around 64 by 64 pixels, so the canvas stays responsive.
- Access to edit the product record, since the image is set on the product, not on the routing.

## Step by Step

1. Open the **Products** area and select or create the product.
2. In the product record, click the image placeholder or camera icon.
3. Browse to the PNG or JPG file. The image is copied to the configured asset storage and its path is stored on the product.
4. Click **Save** (or **Update**) on the product.
5. Open the **BOR** tab and switch to **Designer** mode for the routing that uses this product.
6. The product's node, including the end-product node, now renders the thumbnail. No routing edit is required beyond opening the Designer.

## What Changes When You Save

Saving the product stores the image path on the product record and copies the file into asset storage. From then on, any surface that renders the product reads that path: the routing designer draws the thumbnail on the product node and the end-product node, and the product grid shows it too. This is a display change only. Nothing about scheduling, capacity, timing, or cost is affected by an image. Because the stored path is relative, the display depends on the asset folder staying where it was when you uploaded, so keep assets in the configured location.

## How to Check It Worked

Open the routing in the Designer and confirm the product's node shows the thumbnail rather than a generic icon. Check the product grid as well, where the same image should appear. If the node still shows a generic icon, save the product first and reopen the Designer, and confirm the asset folder has not moved since the upload, which would break the relative path.

## Common Mistakes

- **Uploading a full-size photo.** Large images slow the designer canvas. Use a small thumbnail, around 64 by 64 pixels.
- **Moving the asset folder later.** The product stores a relative path, so relocating assets breaks the display. Keep the folder in place or re-upload.
- **Editing the routing instead of the product.** The image lives on the product record. The node reads it automatically, so there is nothing to attach on the step.
- **Opening the Designer before saving the product.** Save the product first so its image path is stored, then reopen the routing.
