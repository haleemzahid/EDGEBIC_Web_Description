**A work center physical type is a classification label that records what kind of resource a work center represents, such as Machine, Labor, Tool, Material, Energy, Space, IT System, or Financial. It does not change how the scheduling engine allocates hours; its practical roles are the icon shown in the graphical routing editor and the material-versus-labor cost split in quotes.** It answers "what is this resource," separately from how the schedule treats it.

This entry is part of the [EDGEBIC by User Solutions](/edgebic) glossary series; for the wider vocabulary of scheduling, see the [manufacturing glossary](/blog/manufacturing-glossary). The physical type describes the nature of a resource, which is distinct from the [work center type](/blog/what-is-a-work-center-type) that describes the role an operation plays.

## How a Work Center Physical Type Works

Every work center carries a physical type from a fixed list: Machine, Labor, Tool, Material, Energy, Space, IT System, and Financial. The label captures the real-world character of the resource, a CNC mill is a Machine, a quality inspector is Labor, a jig is a Tool, and a consumed raw material is Material.

The key thing to understand is what the label does not do. It does not change scheduling. The engine allocates hours against capacity and shifts identically for every work center, no matter its physical type. Tagging a resource as Tool rather than Machine does not give it different capacity behavior, and switching a type never moves a job.

Where the label earns its keep is in two supporting roles. In the graphical routing editor it drives the icon shown for a step, so a router reading the diagram can tell at a glance which node is a machine, which is labor, and which is material. In quoting, a work center typed as Material is treated specially: its cost is added to the material total rather than the labor total, giving a quote a proper material-versus-labor breakdown.

## A Concrete Example

Picture a routing for a bracket that includes a milling step, an inspection step, and a raw steel plate that is consumed. In the graphical editor, the milling step shows a machine icon because its work center is typed Machine, the inspection step shows a labor icon because its work center is typed Labor, and the steel plate shows a material icon because its work center is typed Material. The icons make the diagram readable without opening each node.

Now the shop quotes this bracket. The quote simulation runs the routing and tallies cost. Because the steel plate's work center is typed Material, its cost lands in the material bucket, while the milling and inspection costs land in labor. The customer sees a clean split: so much for material, so much for labor. Had the steel been modeled on an ordinary Machine-typed work center, the simulation would have folded it into labor or fallen back to a simpler product-cost estimate, and the breakdown would have been wrong.

The physical type changed nothing about when the bracket is scheduled; it changed how the routing reads and how the quote adds up.

## How EDGEBIC Uses It

The physical type is a work-center classification consulted by the editor and the quoting path, not the scheduler.

- **The scheduling engine ignores it** for capacity and allocation, so every work center schedules the same way regardless of physical type.
- **The graphical routing editor** uses it to pick the icon for each step, making a routing diagram readable at a glance.
- **Quoting** treats a Material-typed work center's cost as material rather than labor, producing an accurate material-versus-labor split on the quote.

Because the type feeds the quote's cost categorization, it works alongside the [work center rate in cost rollup](/blog/what-is-a-work-center-rate-in-cost-rollup), which supplies the per-hour figure that turns hours into money. For the fuller picture of how those hours become a costed total, read [what is a cost rollup in manufacturing](/blog/what-is-a-cost-rollup-in-manufacturing).
