**To schedule a downtime event for a machine in EDGEBIC by User Solutions, add a downtime window to the shift the machine runs, set it recurring or one-off, and enter the start and end times.** The scheduler subtracts that window's hours from the shift before it fills any work, so a weekly clean or a planned repair stops eating into promised production.

A downtime event is the right tool when a machine is unavailable for part of a shift, not the whole day. For a machine that is out cold for a full day, reach for [how to block a machine for a maintenance day](/blog/how-to-block-a-machine-for-a-maintenance-day-in-edgebic) instead. This page covers the partial and recurring case. The wider model behind it is in [shifts and calendars explained](/blog/edgebic-shifts-and-calendars-explained).

## Before You Start

- **The work center and its shift already exist** ([how to add a work center](/blog/how-to-add-a-work-center-in-edgebic)).
- **You know the window:** which day or date, and the exact start and end times of the unavailability.
- **You know whether it repeats.** A weekly PM run is recurring; a single planned repair is one-off.

## Step 1: Open the Work Center's Downtime Events

Open the **Work Centers** area and select the machine. Go to its **Downtime Events** tab. This is where the machine's maintenance windows live, attached to the shift it runs.

## Step 2: Add a New Downtime Window

Click **+ Add Downtime**. A new downtime entry opens for editing.

## Step 3: Set the Window and Type

Fill in the window:

| Field | What to enter |
|---|---|
| **Start Date/Time** and **End Date/Time** | The exact span the machine is unavailable. EDGEBIC uses the difference as the subtracted hours |
| **Downtime Type** | Whether the window is scheduled or unscheduled maintenance, used for reporting |
| **Description** | A short reason, such as "Weekly lubrication" or "Annual bearing replacement" |

For a repeating window, mark the event **recurring** and choose the **day of week**. A recurring event fires on every matching weekday. For a single repair, leave it one-off and set the specific **date**; it fires only on that day.

## Step 4: Save

Click **Save**. The downtime window is now attached to the machine's shift.

## What Changes When You Save

| Surface | Effect |
|---|---|
| The machine's capacity on affected days | Drops by the window's duration, before instance and utilization math |
| Resource Calendar and capacity views | Show the reduced hours when refreshed |
| Existing schedules | Unchanged until you rerun |
| Next **Drive Schedule** run | Books only the remaining hours; work that no longer fits slides later |

A worked case: a milling cell on an 8-hour day shift with a recurring 2-hour Monday PM window now offers 6 hours every Monday. If a 7-hour job was landing on that Monday, the next run places 6 hours there and spills the last hour into Tuesday.

## How to Check It Worked

1. Open the Resource Calendar and read the machine's available hours on a day the window applies. A one-instance 8-hour shift with a 2-hour recurring window should read 6 hours, not 8.
2. For a recurring event, check a second matching day to confirm it repeats.
3. Run **Drive Schedule** and confirm no bars sit inside the protected window. Work that was there should have moved to later hours or the next day.

## Common Mistakes

**Entering a window longer than the shift.** EDGEBIC floors capacity at zero, so an overrunning window silently blanks the day. If a machine unexpectedly shows zero hours, check for a downtime event that overruns its shift. Use a per-day override or a full-day closure for genuine all-day outages.

**Using a downtime event for a full-day teardown.** A downtime event is for partial-shift losses. For a machine out all day, a per-day capacity override of zero is clearer and carries its own audit reason.

**Forgetting to rerun.** The window reduces capacity, but jobs already on the plan do not move until the next scheduling run. Adding the event and walking away leaves the old bars sitting through the window on screen.

**Confusing a PM window with a PM reminder.** A downtime event blocks the hours while maintenance happens. It does not warn you that maintenance is due. To get an on-machine "PM due" banner, set the interval separately, covered in [how to set a preventive maintenance reminder for a machine](/blog/how-to-set-a-preventive-maintenance-reminder-for-a-machine-in-edgebic).
