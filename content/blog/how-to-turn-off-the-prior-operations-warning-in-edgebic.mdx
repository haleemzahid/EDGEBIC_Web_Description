**The prior-operations warning in EDGEBIC is a data-integrity safety gate, and it has no off switch by design: you stop it firing by logging actuals on earlier operations first, or by accepting the one-click auto-backfill it offers.** The adjacent drag warnings do have configuration toggles, but the missing-prior-actuals prompt in EDGEBIC by User Solutions is deliberately not one of them, because turning it off would let gaps into a job's history that the reschedule engine cannot reason about.

This post covers that one prompt and its neighbors. For what the safety prompts are protecting and why, read [EDGEBIC Gantt safety prompts and prior operations](/blog/edgebic-gantt-safety-prompts-prior-operations); the full task library is at the [EDGEBIC how-to hub](/blog/edgebic-how-to-hub).

## Before You Start

- You have hit the **Batch Scheduling** prompt that reads "Warning! No actual dates logged to prior workcenters!" when saving a change on the Gantt.
- You understand the prompt fires when a later operation gets an actual while its earlier operations in the same job have none.
- You can reach the scheduler configuration if you want to adjust the related, toggleable warnings.

## The Steps

You cannot switch the missing-priors prompt off, so the task is really "stop it appearing." Two paths do that, and two related warnings can be disabled outright.

1. **Log front to back.** Record actuals on the earliest operation first and work forward. By the time you save a later operation, its priors already carry actuals and the prompt never appears.
2. **Or accept the auto-backfill.** When the prompt appears, click **OK**. EDGEBIC fills the earlier operations with their planned dates as actuals, tagged so a report can tell auto-filled values from hand-logged ones. Click **Cancel** instead if you would rather go and log them properly.
3. **To silence the target-start warning**, enable **Disable Target Start Date Check** in the scheduler configuration. This stops the status-bar warning about dragging a bar before its target start.
4. **To silence the out-of-sequence warning**, untick **Scheduler Update Warning** on the configuration's General tab. This stops the post-save prompt about jobs that may have fallen out of order.

## What Changes When You Save

| Setting or action | Effect |
|---|---|
| Log priors first | The missing-priors prompt does not fire; nothing to accept or cancel. |
| Accept the auto-backfill (OK) | Earlier operations get planned dates as actuals, tagged as auto-filled; the save completes. |
| Disable Target Start Date Check | The drag-before-target-start warning stops appearing; the engine still respects the date on the next run. |
| Untick Scheduler Update Warning | The post-save out-of-sequence prompt stops appearing. |
| The missing-priors prompt itself | Always on. There is no toggle for it. |

## How to Check It Worked

Save a change on a downstream operation whose priors you have just logged. The prompt should not appear. Then drag a bar before its target start with **Disable Target Start Date Check** enabled; the status-bar warning should stay silent. If the missing-priors prompt still appears after you thought you logged the priors, one earlier operation is still without actuals; the prompt lists exactly which work centers are missing.

## Common Mistakes

**Treating the missing-priors prompt as a bug to suppress.** It is a guard, not a nag. Logging front to back removes it cleanly; there is no supported way to turn it off, and that is intentional.

**Confusing the three warnings.** The missing-priors prompt, the target-start-date check, and the out-of-sequence warning are three separate things. Only the last two have configuration switches. Turning off one does not affect the others.

**Disabling the target-start check to fix accidental early drags.** The warning exists to catch exactly those accidents. Turn it off only if your planners pull operations earlier than their target start knowingly and routinely; otherwise leave it on.

**Forgetting the auto-backfilled tag.** When you accept the auto-fill, those actuals are marked as system-filled. If you later reconcile actual hours, treat the tagged values as estimates from the plan, not as floor-reported truth.
