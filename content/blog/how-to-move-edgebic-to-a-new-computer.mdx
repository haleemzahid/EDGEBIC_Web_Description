**To move EDGEBIC to a new computer for a single-user install, export the database on the old PC from Settings and then DataSource, install EDGEBIC on the new PC, copy the exported file across, then point the connection at it with Browse and Apply and restart.** In EDGEBIC by User Solutions the local database is a single file, so copying it moves the whole system, and users travel inside the database: you sign in on the new machine with the same accounts. The only thing that does not travel is a saved SQL Server password, which is account-bound and re-entered.

This post covers moving a single-user install. To make the snapshot the move relies on, see [how to back up the EDGEBIC database](/blog/how-to-back-up-the-edgebic-database); the full task library is at the [EDGEBIC how-to hub](/blog/edgebic-how-to-hub).

## Before You Start

- You know whether the install is single-user (a local file) or shared (a SQL Server database). The two paths differ.
- You have the installer for the new PC and administrator rights to run it.
- If you use SQL Server authentication, you have the SQL password to hand, because it will not carry across.

## The Steps

**Single-user install (local file):**

1. **Export the database on the old PC.** Open **Settings**, then **DataSource**, and click **Export** on the connection card. This makes a clean, consistent snapshot even while the application is open.
2. **Note the file path.** The connection card shows the exact path of the live database if you prefer to copy that instead of the export (close EDGEBIC first if you copy the live file).
3. **Install EDGEBIC on the new PC** and copy the exported file onto it.
4. **Point the connection at the copied file.** On the new PC open **Settings**, then **DataSource**, keep the provider on **SQLite**, use **Browse** to select the copied file, and click **Apply and restart**.
5. **Sign in.** Use the same accounts as before; users live inside the database.

**Shared install (SQL Server database):**

1. **Install EDGEBIC on the new PC.** There is no data to copy.
2. **Point at the same database.** Open **Settings**, then **DataSource**, choose **SQL Server**, and enter the same server and database.
3. **Re-enter the SQL password if needed.** For SQL authentication, re-enter the password under the new Windows account. Windows authentication needs no re-entry. Click **Apply and restart**.

## What Changes When You Save

| Surface | Effect |
|---|---|
| The database | For single-user, the copied file becomes the active database on the new PC. |
| User accounts | Travel inside the database; the same sign-ins work. |
| SQL Server password | Does not travel; re-entered on the new machine under the new account. |
| Display configuration and labels | Travel if you exported them to a file and import on the new PC. |
| The old PC | Untouched; its database remains as a fallback until the move is confirmed. |

## How to Check It Worked

On the new PC after the restart, open **Settings** and then **DataSource** and confirm the connection card shows the copied file (single-user) or the same server and database (shared), with a green Connected chip. Then open **Job View** and confirm your orders and schedules are exactly as they were on the old machine. Sign in with an existing account to confirm users came across. When the data and accounts match, the move is complete and you can retire the old PC.

## Common Mistakes

**Copying the live file while EDGEBIC is open.** A hot copy of the live file can catch an in-progress write. Use Export for a consistent snapshot, or close the application before copying the file directly.

**Expecting the SQL password to travel.** It is encrypted against the original Windows account and cannot be decrypted elsewhere. Re-enter it on the new machine, or use Windows authentication to avoid the issue.

**Copying files for a shared install.** With a shared SQL Server database there is nothing to copy. Install EDGEBIC and point it at the same server and database.

**Deleting the old install too soon.** Keep the old PC's database until the new machine has run real scheduling for a while. It is your fallback if anything looks wrong.
