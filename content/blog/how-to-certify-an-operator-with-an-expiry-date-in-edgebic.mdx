**To certify an operator with an expiry date in EDGEBIC by User Solutions, open the operator's Skills tab, add the certification, and set the expires-on date.** The control lives in the Operators area, on the selected operator's Skills tab, where each row links one operator to one skill with a certified-on date, an expires-on date, an optional proficiency level, and an active flag. EDGEBIC counts the operator as qualified for that skill until the expiry passes, then filters the lapsed certification out on the next scheduling run so the schedule never assumes a stale credential is valid.

This is one specific task. For the wider labor model and how certifications feed the schedule, read [EDGEBIC operator and skill scheduling explained](/blog/edgebic-operator-and-skill-scheduling-explained).

## Before You Start

- The operator already created in the Operators area.
- The skill already in the skills catalog. If the skill does not exist yet, create it first.
- The certified-on and expires-on dates for this credential. Leave the expiry blank only for a credential that genuinely never lapses.

## Step by Step

1. In **Daily Hours**, open the **Operators** area and select the operator.
2. Open the operator's **Skills** tab.
3. Add a certification and choose the **Skill** from the list.
4. Set **Certified On** to the date the operator earned the credential.
5. Set **Expires On** to the date the credential lapses. Leave it blank for a credential that never expires.
6. Optionally record a proficiency **Level**.
7. Keep the certification **Active**, and save.

## What Changes When You Save

The certification links the operator to the skill for the qualified pool. When EDGEBIC builds its operator data for a scheduling run, it includes the certification only if it is active and not expired. So on every run up to the expiry, the operator counts toward any skill step requiring that skill, contributing their rostered hours to the pool. Once the expiry has passed, the certification is filtered out and the operator no longer counts as qualified for that skill, so steps that needed them find someone else or slide.

Recording a certification does not move the current schedule on its own. It takes effect on the next Drive Schedule or reschedule run.

## How to Check It Worked

Require the skill on a test step, or reuse one that already requires it, and reschedule. The newly certified operator should now appear in the operator booking lines in the session log for that skill, and on the operator calendar as available hours against that skill's pool. To confirm the expiry behaves, set an expiry in the past on a spare certification and reschedule: that operator should drop out of the qualified pool for the skill.

## Common Mistakes

- **A past expiry silently removes the operator.** If someone vanishes from the qualified pool without being deactivated, check for a lapsed expiry date. Expired certifications are filtered out at run time by design. Record the renewal with a new expiry to bring the operator back.
- **Assuming mid-horizon expiry is honored day by day.** A certification that expires inside the planning window is treated as expired for the whole run, not valid up to the lapse date. Plan around the recertification or record the renewal before scheduling past the old expiry.
- **Deleting instead of deactivating for a temporary hold.** To suspend a credential during retraining, set it inactive. Deleting loses the certified-on date and any level you recorded.
- **Leaving the expiry blank by accident.** A blank expiry means the credential never lapses. For a certification that must be renewed, always set the expires-on date, or the schedule will keep counting a credential that has really expired.
