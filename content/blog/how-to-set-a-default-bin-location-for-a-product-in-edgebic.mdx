**To set a default bin location for a product in EDGEBIC by User Solutions, open the product, go to the Inventory Planning section, and type a location string into Default Bin Location, then save.** From then on, every new inventory ledger entry for the product carries that location, so receipts, issues, and adjustments all read with a consistent storage tag. It is a product-level convenience that makes the ledger clearer and prepares records for future warehouse tracking. The tag applies to new entries only and does not rewrite history.

This is one product setting. To see the entries it stamps, read [how to audit the inventory ledger for a part](/blog/how-to-audit-the-inventory-ledger-for-a-part-in-edgebic). The full task set is on the [EDGEBIC how-to hub](/blog/edgebic-how-to-hub).

## Before You Start

- The product exists and is stocked, so it posts ledger entries.
- The storage location you want to record, as a short text string up to 100 characters.
- An understanding that the tag applies to future entries, not to entries already posted.

## Step by Step

1. Open the **Products** tab and edit the product.
2. Scroll to the **Inventory Planning** section.
3. Type the location into **Default Bin Location**, for example Rack A3.
4. Click **Save**.

## What Changes When You Save

Every new inventory ledger entry for the product now copies your string into its location field. Receipts, issues, and adjustments posted from this point forward carry the tag, so the ledger reads consistently and shows where the product lives. If you leave the field blank, entries fall back to a generic default location, which still posts correctly but tells you less. Existing entries are not changed, because EDGEBIC stamps the location at the time an entry is written and does not rewrite history.

Location tracking is product-level at this stage. It is a readability and audit convenience today, and a foundation for finer warehouse tracking later.

## How to Check It Worked

Post a small receipt or adjustment for the product, then open its ledger and confirm the new entry carries your location string. Compare it against an older entry, which should keep its original location, confirming the tag applies going forward only. If the new entry shows the generic default instead of your string, confirm the field saved on the correct product.

## Common Mistakes

- **Expecting old entries to update.** The tag applies to new entries only. History keeps its original location.
- **Treating it as a stock move.** Changing the field does not physically move recorded stock. A move is a transaction, not a field edit.
- **Exceeding the length limit.** Keep the string within 100 characters. Use a short, consistent naming scheme.
- **Assuming it is required.** A blank field still posts entries under a generic default. Set it only when the location matters to you.
