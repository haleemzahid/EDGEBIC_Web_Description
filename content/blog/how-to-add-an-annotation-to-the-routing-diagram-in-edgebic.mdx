**To add an annotation to the routing diagram in EDGEBIC by User Solutions, open the routing in the Designer and click Add annotation on the toolbar.** The button drops a free-floating sticky note onto the canvas that you can position anywhere and type into. Right-click a note to edit or delete it. Annotations are documentation only: the scheduler ignores them entirely, so they never touch timing, capacity, or the plan. They exist to carry context for the next planner, such as why a step is shaped the way it is or that a branch is pending a decision.

This recipe covers one specific task: a canvas-level note. For a remark attached to a single operation, see [how to add a note to a routing step](/blog/how-to-add-a-note-to-a-routing-step-in-edgebic). For a tour of the visual editor, read [EDGEBIC graphical BOR designer tour](/blog/edgebic-graphical-bor-designer-tour) and [how to build a routing as a flow chart](/blog/how-to-build-a-routing-as-a-flow-chart-in-edgebic).

## Before You Start

- The routing open in the Designer. Annotations are a Designer feature and live on the diagram canvas.
- The message you want to record, and a sense of where on the canvas it belongs, since a note is free-floating and you position it yourself.
- A reminder that this is documentation only. If you actually need to change timing or capacity, edit the step's fields instead.

## Step by Step

1. Open the **BOR** tab and switch to **Designer** mode.
2. Click **Add annotation +** on the toolbar. A sticky note appears on the canvas.
3. Drag the note to the position you want, for example beside the branch or step it comments on.
4. Type your remark into the note.
5. To change or remove it later, right-click the note and choose **Edit** or **Delete**.
6. Click **Update** to save the routing so the annotation persists with the diagram.

## What Changes When You Save

Saving stores the annotation with the routing diagram, so it reappears the next time anyone opens the Designer for that routing, in the same place. Nothing else changes: the scheduler does not read annotations, so no timing, capacity, or date is affected. This is the whole point of the feature. You can add as many notes as you like without any risk to the plan, which makes annotations a safe way to leave context that a step's own fields cannot express, such as a reason, a caveat, or a pending decision.

## How to Check It Worked

After saving, the annotation should remain on the canvas at the position you placed it. Reopen the routing in the Designer to confirm it persisted rather than living only in your current session. Run a schedule and confirm the plan is unchanged from before you added the note, which verifies the annotation is documentation only and did not alter anything.

## Common Mistakes

- **Using an annotation to change the plan.** Annotations are ignored by the scheduler. If you need a real delay or a capacity change, edit the step's fields.
- **Closing without saving.** An unsaved annotation is lost like any other unsaved Designer edit. Click Update before leaving.
- **Confusing an annotation with a step note.** An annotation floats on the canvas and belongs to no step. A step note is the Description field on one row. Pick the one that matches where the remark belongs.
- **Overloading the canvas.** Too many notes clutter a large diagram. Keep them short and place them near what they describe.
