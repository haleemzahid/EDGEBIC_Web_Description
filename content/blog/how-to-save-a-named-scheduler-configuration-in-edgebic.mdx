**To save scheduler settings under a new name in EDGEBIC by User Solutions, tune the Schedule configuration panel and click Save As, which creates a fresh named configuration and leaves the one you started from alone.** From there you can switch between named configurations, flag one as your startup default, and move a configuration to another machine with Export and Import.

Named configurations are what stop the "please put the colors back" conversation. Instead of resetting and rebuilding, you keep two or three views and switch. For the emergency route back to factory settings, see [how to reset scheduler settings to defaults](/blog/how-to-reset-scheduler-settings-to-defaults-in-edgebic).

## Before You Start

- You have the Settings permission, or the Settings tab is hidden.
- You have a reason for a second configuration. Good ones: a dense timeline for detail work, a wide month view for capacity meetings, a high-contrast layout for a floor screen.
- You have a name in mind. The generated name is timestamped and unmemorable, and renaming it later is a small job you will forget to do.

## Saving Under a New Name

1. Open the **Settings** tab and go to the **Schedule** configuration panel.
2. Adjust the settings you want in this view: view types, operation-state colors, bar-label patterns, timeline scale, and the rest.
3. Click **Save As**. EDGEBIC creates a new configuration entry, gives it a generated name based on the current one plus a timestamp, and switches you onto the copy.
4. Rename it to something readable while you still remember its purpose.

The configuration you started from is untouched. That is the whole point of **Save As** rather than the normal save: the ordinary save writes over the configuration you are on.

## Switching Between Configurations

1. Open the **available configurations** list in the Schedule panel.
2. Select the configuration you want. Selecting it loads it into the panel and the live view.

Loading a configuration does not delete or alter the others. You can bounce between them as often as you like.

## Setting a Startup Default

1. Load the configuration you want as your default.
2. Click **Set as Default**.

That configuration is flagged as the default and the flag is cleared from every other one, so there is always exactly one. Next launch opens on it.

The default is per user. On a shared database, a planner and a supervisor can each start in a different view of the same plan without stepping on each other.

## Copying a Configuration to Another Machine

| Step | Button | What happens |
|---|---|---|
| 1 | **Export** | Writes the loaded configuration to a file you choose |
| 2 | **Import** (on the other machine) | Reads the file into the panel, not yet saved |
| 3 | **Save and Apply Now Configuration** | Persists it and applies it to the live view |
| 4 | **Set as Default** | Makes it that user's startup view |

Step 3 is the one people skip. An imported configuration sits in the panel unsaved until you apply it, and closing the panel first loses the whole thing.

One caveat on export files: the configuration includes work center display resources, which are specific to the database it came from. Importing onto a database with a different work center list usually still works but may need a look at the resource list afterward.

## How to Check It Worked

Open the available configurations list. Your new name should be there alongside the one you copied from, and the panel should show the new name as current. Switch to the other configuration and back to confirm both load cleanly.

For the default, close EDGEBIC and reopen it. You should land on the configuration you flagged, not on the last one you happened to be using.

## A Quick Worked Example

A planner runs the plant from a laptop during the day and drives a wall-mounted screen at the 7 a.m. stand-up.

She tunes her working view first: compact timeline, all view types enabled, detailed bar labels showing job number and dates. She clicks **Save As**, renames the copy **Planner Detail**, and clicks **Set as Default** so it opens there every morning.

Then she changes the same panel for the wall screen: fewer view types, larger scale, high-contrast operation-state colors, and a short bar label that reads at three meters. She clicks **Save As** again and names it **Standup Screen**. Now she has two entries in the list and switches with a single selection before the meeting.

Finally she loads **Standup Screen** and clicks **Export**, saving the file to the shared drive. The supervisor who runs the meeting when she is away imports it on his own machine, clicks **Save and Apply Now Configuration**, and the board looks identical whoever is driving it.

## Common Mistakes

**Using the normal save when you meant Save As.** The ordinary save overwrites the configuration you are on. If you were tuning a variant on top of a good view, you have just lost the good view.

**Leaving the generated timestamp name.** Three entries called something-copy-followed-by-digits are indistinguishable in a month. Rename immediately.

**Importing without applying.** The imported settings are not persisted until you click **Save and Apply Now Configuration**.

**Deleting the configuration that was the default.** Deleting it does not promote another one, so no default remains and the next launch falls back to the built-in settings. Set a new default after any delete.

**Expecting a configuration to change the plan.** These are display and interaction settings only. Switching configurations never moves a job or changes a date.
