**To add move time between operations in EDGEBIC by User Solutions, enter the move hours on the routing step whose parts are transported onward, then optionally turn on the Show Move Time display so the transport shows on the Gantt.** Move time is a cost and display figure. It adds to the routing step's total-time cost rollup and can be drawn as a segment between operations, but it is not used in capacity allocation, so it does not push the next operation's start date later. Reach for it when you want the internal transport between two operations to appear in cost estimates and, if you choose, on the schedule view.

This recipe covers one specific task. For the buffers that genuinely delay a downstream step, read [how EDGEBIC composes step timing](/blog/how-edgebic-composes-step-timing) and [EDGEBIC queue and transit times explained](/blog/edgebic-queue-and-transit-times-explained). For the routing itself, see [EDGEBIC Bill of Routing explained](/blog/edgebic-bill-of-routing-explained).

## Before You Start

- The routing open, with the step whose parts are moved to the next operation identified.
- The move duration in hours, and a clear decision on whether the move should also delay the next step. If it should, plan to add queue time or transit days as well, because move time alone does not.
- Access to Settings if you want the move segment drawn on the Gantt.

## Step by Step

1. Open the **BOR** tab and select the routing.
2. Select the step whose parts are transported to the next operation (for example, the milling step before painting).
3. Enter the move hours for that step. This value feeds the step's total-time cost rollup.
4. Click **Update Standard BOR** to save.
5. To render the move on the schedule, open **Settings**, go to the **Manufacturing** tab, and under the setup and queue time segment options turn on **Show Move Time**. The Gantt then draws a move segment between operations.
6. Run **Generate Schedule** if you want the cost and any display change reflected in a fresh plan.

## What Changes When You Save

Saving the move hours updates the routing's cost math immediately: the step's total time now includes the transport, so the estimated cost of the routing and any new quote simulation reflect it. The scheduled operation window does not grow, because move time is a cost element and is not consumed as capacity. With Show Move Time on, the Gantt draws a move segment between the two operations, which is purely a visual overlay. Nothing on the plan's dates shifts from move time alone. If you also need the parts to wait before the next operation, that delay must come from queue time or transit days, which are the buffers the scheduler acts on.

## How to Check It Worked

Open the routing's cost estimate or run a quote simulation and confirm the total reflects the added transport time. If you enabled Show Move Time, open the Job View Gantt and look for the move segment between the two operations. Confirm the downstream operation's start date has not changed, which is the correct behavior: if it moved, something else on the step (queue, flow, or transit) is responsible, not the move hours.

## Common Mistakes

- **Expecting move time to delay the schedule.** It does not. Move time feeds cost and display only. Use queue time or transit days for a real gap.
- **Doubling up transport delay.** If you already model the physical gap with transit days, adding move hours to represent the same trip only inflates cost. Decide whether the trip is a costed figure, a scheduling gap, or both, and set each field once.
- **Looking for the segment without enabling it.** The move segment does not appear on the Gantt until Show Move Time is turned on in Settings. It is off by default.
