**To save a grid layout in EDGEBIC, simply arrange the grid: resize, reorder, hide, pin, sort, group, or filter its columns, and EDGEBIC saves that arrangement automatically when you navigate away or close the window.** There is no Save Layout button by design in EDGEBIC by User Solutions, and the layout returns exactly as you left it the next time you open that grid, held per grid and per user.

This post covers the one task. For the wider set of display and configuration choices around it, read [EDGEBIC configuration options explained](/blog/edgebic-configuration-options-explained); the full task library is at the [EDGEBIC how-to hub](/blog/edgebic-how-to-hub).

The persistence is broad on purpose. It covers the configurable grids and trees across the main tabs, the report panes, the dialogs, and the pickers, including the Job View job tree, so the work you put into any one of them sticks the same way. Report panes that carry a data grid get it without any setup at all, which is why you never see a Save Layout button anywhere: the behavior is uniform, not a per-screen feature you have to switch on.

## Before You Start

- You are signed in under your own account. Layouts are saved per user.
- You know which grid you want to arrange. The behavior covers the main-tab grids, report panes, dialogs, pickers, and the Job View job tree.
- You understand that layout is display only; it never changes the schedule or the data in the rows.

## The Steps

1. **Open the grid or tree** you want to arrange.
2. **Adjust the columns**: drag a border to resize, drag a header to reorder, right-click a header to hide or show columns, pin a column, sort, group, or apply a column filter.
3. **Navigate away** from the grid, or close the window. The arrangement saves at that moment.
4. **Reopen the grid** to confirm your layout returns exactly as you left it.

That is the whole task. There is no button to click, because the save is automatic on navigate-away and on close.

## What Changes When You Save

| Surface | Effect |
|---|---|
| Column widths, order, visibility | Restored on next open, per grid and per user. |
| Pinning, sorting, grouping, filters | All persisted alongside the column arrangement. |
| A newly shipped column | Still appears after an update; it is reconciled against your saved layout rather than hidden. |
| Other users | Nothing. Each account carries its own saved layouts. |
| The plan and the data | Nothing. Layout is presentation only. |

## How to Check It Worked

Rearrange a grid, navigate to another tab, and come back. Your columns should be exactly as you left them. Close and reopen the whole application and check again; the layout should survive that too. If it does not, confirm you are signed in under the same account both times, since layouts are keyed to the user.

## Common Mistakes

**Hunting for a Save Layout button.** There is not one. The absence is intentional; the layout saves itself when you leave the grid. If you keep looking for the button, you may be tempted to think nothing saved, when in fact it already did.

**Sharing one account on a shared station.** Layouts are per user. If two planners sign in under the same account, they overwrite each other's arrangement on every navigate-away. Use separate accounts.

**Assuming an update wiped your columns.** A new column is merged into your layout, not dropped over it. If a grid looks off after an update, rearrange it once and it re-saves cleanly.

**Reaching for a reset before trying a rearrange.** Most "stuck" grids fix themselves the moment you rearrange and navigate away. Only if that fails do you need the layout-reset guidance on the Data Management tab under Settings.

**Hiding the only column of a single-column list.** A few narrow pick lists carry just one column. Hiding it leaves the list permanently blank with no obvious way back, so leave single-column lists alone; the persistence is meant for grids where there is genuinely something to rearrange.
