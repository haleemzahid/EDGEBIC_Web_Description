**Stopping the optimizer early still gives you a valid plan: EDGEBIC keeps the best schedule found so far, and it can return that plan, already checked and safe to apply, the moment you interrupt.** An interrupt costs you the chance of further improvement, never the plan itself.

EDGEBIC by User Solutions builds every optimization to be time-boxed and interruptible, which means you are never trapped waiting for a run to finish before you can act. This is the anytime property: at any moment, the optimizer has a usable answer ready. Understanding it explains why a long time budget is safe to set and why an interrupt is a normal, supported action rather than an emergency. For the wider optimizer picture, see the [EDGEBIC optimizer guide](/blog/edgebic-optimizer-guide).

## The incumbent: always a plan in hand

The key idea is the incumbent, the best valid plan the optimizer has found up to the current moment. From early in a run, the optimizer holds an incumbent and keeps replacing it whenever it finds something better. The incumbent is not a rough sketch. It is a complete, decoded schedule that has already cleared the same checks any final result must pass.

That means at any instant, there is a real plan ready to return. Whether the run finishes on its own, the solver proves it is done, or you interrupt it, the optimizer hands back the incumbent it is holding. You are never given a partial or broken schedule as the price of stopping early. The worst case of an interrupt is that the incumbent is not quite as good as it might have become with more time, and even then it is at least as good as where you started.

## What the incumbent has already passed

An interrupted result is safe because the incumbent has already been through the same protections as a completed one. It has been scored against your baseline with the shared calculator and kept only because it does not lose to the baseline on your goal, the never-worse guarantee covered in [the never-worse guarantee in schedule optimization](/blog/the-never-worse-guarantee-in-schedule-optimization). It has cleared the structural safety gate, so it contains no dropped jobs and no inverted dates.

Because those checks are what qualify a plan to be the incumbent in the first place, there is no separate validation step that an interrupt could skip. The plan you get from stopping early is held to the same standard as the plan you would get from letting the run finish. The only variable is how much better it might have gotten.

## Three ways a run ends

An optimizer run reaches its conclusion in one of three ways, and all three return the best valid plan available.

The first is a natural finish within the time budget: the search exhausts what it can try, or the solver works through its passes, and the optimizer returns its final incumbent. The second is an early proof: the mathematical solver reaches a plan it can prove is the best possible for your goal and stops immediately, because continuing would gain nothing. The third is your interrupt: you stop the run, and the optimizer returns whatever incumbent it holds at that moment. This is why a run given a long budget can still return in seconds. It proved it was done, described in [how a proven optimality gap builds trust](/blog/how-a-proven-optimality-gap-builds-trust).

## The bound survives an interrupt

For the mathematical solver, an interrupt gives you more than just a plan. It gives you the bound the solver had proven so far. The bound is the solver's certificate of how good the best possible plan could be, and together with the incumbent it produces the optimality gap: the honest distance between the plan you have and the best that could exist.

Stopping early does not erase this. You get the incumbent and the gap as of the moment you interrupted. The gap may be wider than it would have been after a full run, because the solver had less time to tighten it, but it is truthful. A wide gap tells you there may be meaningful room left and more time could help. A narrow gap tells you the interrupted plan is already close to optimal and probably good enough to apply now. Either way, you are deciding with real information, not guessing.

## Why this makes the time budget safe to set generously

The anytime property changes how you think about the time budget, covered in [setting the optimizer time budget](/blog/setting-the-optimizer-time-budget). Because an interrupt always yields a valid incumbent, the budget is a ceiling on how long the optimizer may search, not a commitment you are locked into.

You can set a generous budget for an overnight or between-shifts run, knowing the solver will stop early if it proves optimality and you can stop it early yourself if you need the answer sooner. There is no penalty for giving it more time than it turns out to need, and no risk that a long budget strands you waiting. Set the budget to the most time the situation can spare, and take the answer whenever you actually need it.

## Interrupt, then decide as usual

An interrupted result flows into the same review you would have anyway. The optimizer presents the incumbent as its proposal, with the comparison table and, for the solver, the gap. You read the deltas exactly as you would for a completed run, and you Accept to apply the plan or Discard to keep your current schedule. Nothing about the interrupt changes that final step.

So stopping early is not a special mode with different rules. It is the ordinary optimizer flow, entered a little sooner. You get a valid plan, you see how good it is, and you stay in control of whether it lands.

## The bottom line

Stopping the optimizer early is a supported, safe action, not a failure. The optimizer always holds an incumbent, the best valid plan found so far, and it can return that plan the moment you interrupt, already clamped never worse than your baseline and cleared by the safety gate. The solver hands back its proven bound too, so you still see an honest optimality gap. That anytime behavior makes the time budget a ceiling rather than a commitment: give the optimizer as much time as you can spare, and take a valid answer whenever you need one.
