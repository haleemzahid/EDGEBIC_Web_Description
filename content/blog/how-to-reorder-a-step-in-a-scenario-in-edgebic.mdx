**To reorder a step in a scenario in EDGEBIC, open the quote's Scenarios view, add a step override, set the Override Type to Reorder, and enter the new Sequence number, then click Run Simulation.** The step moves to the new position inside that scenario only. The real routing keeps its original sequence.

A scenario in EDGEBIC by User Solutions is a named what-if variant of a quote's simulation. A Reorder step override is the lever for testing "what if the operations ran in a different order," for example moving inspection earlier so rework is caught sooner, or running a slow step first so downstream work overlaps it. The resequence is confined to the scenario, so you can test the idea before touching the real routing.

## Before You Start

- **A quote exists and has been simulated once.** Scenarios are children of a quote, and the base simulation is your comparison baseline. See [how to create a what-if scenario](/blog/how-to-create-a-what-if-scenario-in-edgebic).
- **You know the step and its new sequence number.** Reorder needs the routing step and the position you want it in.
- **You understand the dependency risk.** Moving a step that feeds a later one can produce dates that are physically impossible.
- **You keep a baseline scenario.** A no-override Standard scenario is what you compare the resequence against.

## Step 1: Open the Scenario View

On the **Quote** tab, select the quote and click **Scenarios**. The What-If Scenario Analysis view opens. Select an existing scenario or click **Create New Scenario** and name it after the lever, for example `Deburr before paint`.

## Step 2: Add a Step Override

In the **Production Step Overrides** group, click **Add Step Override**. A new override row appears.

## Step 3: Pick the Step and Set Reorder

Choose the **Step**, then set **Override Type** to **Reorder**. The sequence field becomes relevant.

| Override Type | Effect in this scenario | You also fill in |
|---|---|---|
| **Reorder** | The step moves to a new position in the sequence | **Sequence #** |

## Step 4: Enter the New Sequence Number

Type the **Sequence #** that places the step where you want it. A lower number runs earlier in the routing; a higher number runs later. This is the position the scenario will simulate.

## Step 5: Run the Simulation

Click **Run Simulation**. Read the **Simulation Results**: **Estimated Start Date**, **Estimated End Date**, **Lead Time**, **Total Hours**, and **Estimated Cost**. Each run overwrites this scenario's stored results, and nothing touches the shop plan.

## What Changes When You Save

| Action | What changes | What does NOT change |
|---|---|---|
| **Run Simulation** | The scenario's stored dates, hours, and cost | The production schedule, the quote, the real routing |
| **Apply to Quote** | The parent quote's estimated numbers | The product's real step sequence |

## How to Check It Worked

1. Confirm the override row shows **Reorder** and the new sequence number.
2. Click **Run Simulation** and note the new **Estimated End Date**.
3. Sanity check the dates: make sure no step now simulates before an operation it truly depends on.
4. Open the **Comparison Analysis** tab, tick this scenario and a Standard baseline, and read the Lead Time chart. Confirm the real routing sequence is unchanged in the BOR editor.

## Common Mistakes

**Breaking a dependency.** Moving a step ahead of the operation it feeds lets that operation simulate too early. Always read the resulting dates for plausibility before trusting a reorder.

**Reordering when a time or machine change is the real lever.** If the goal is a faster step, use ModifyTime. If it is a different machine, use Replace. Reorder only changes position.

**Forgetting to re-simulate.** The override does nothing until you click Run Simulation.

**Treating the scenario as a real change.** Applying a winning scenario copies its numbers onto the quote only. Update the real routing sequence in the BOR editor before converting the quote.
