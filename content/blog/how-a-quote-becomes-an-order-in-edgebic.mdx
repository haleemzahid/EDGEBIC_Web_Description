**Converting a quote to an order in EDGEBIC turns an approved enquiry into a live Manufacturing Order with one click, carrying every cost, date, and link forward so nothing is re-typed.** In EDGEBIC by User Solutions, the approved quote already holds the capacity-aware plan: simulated dates, rolled-up costs, markup, price, and the customer relationship. Conversion copies all of it onto a new Manufacturing Order named after the quote, flips the quote to a final Converted status, and guards against ever doing it twice. The order then reproduces the plan you sold, because it inherits the same scheduling direction the quote used.

## Why re-keying is the enemy

In many shops the quote lives in one place and the work order is typed somewhere else. A salesperson agrees a quantity, a price, and a date, and then a planner reads that quote and re-enters it as a production order. Every retyped field is an opportunity for error: a quantity off by a digit, a lost customer PO reference, a price that no longer matches what the customer signed.

Worse, the two records drift over time. The quote said 200 units at a 25-day lead time; the work order says 250 because someone rounded up. When the invoice does not match the quote, the argument is with the customer, and the shop loses either the margin or the relationship.

Conversion closes that gap by making the order a direct descendant of the quote. There is no second data-entry step, so there is nothing to get wrong.

## What carries forward

When you convert, EDGEBIC creates a Manufacturing Order and copies these fields from the quote:

| From the quote | Onto the Manufacturing Order |
|---|---|
| Product and quantity | Product and quantity |
| Requested date | The order's due date |
| Simulated start and end dates | The order's target start and planned window |
| Scheduling direction | The order's direction, so the real run reproduces the quoted plan |
| Estimated cost, labor and material split, hours | The order's estimate fields, feeding quote-versus-actual variance later |
| Markup percent and unit price | Kept for margin reporting |
| Customer and sales-order links | Kept, with no re-keying |

The job number is deterministic: for quote QUO-2026-011 the order is named MO-QUO-2026-011. That naming makes the lineage obvious on the Gantt, in reports, and in any later variance analysis.

Carrying the estimate fields matters beyond convenience. Because the order stores what the quote predicted, EDGEBIC can later compare quoted hours and cost against the hours and cost actually burned once the job runs. That quote-versus-actual variance is only possible because the numbers were carried, not retyped.

## A worked example

Quote QUO-2026-011 is for 200 units of Widget-A. It has been simulated, so it carries a capacity-aware plan: start 07/20/2026, end 08/14/2026, estimated cost $9,230, unit price $85, total price $17,000, customer Acme Industries, forward scheduling direction. The customer signs and the status moves to Approved.

The planner clicks the Convert to Order icon. EDGEBIC runs three checks in order:

1. The quote status is not already Converted. Pass.
2. No existing Manufacturing Order links back to this quote. Pass.
3. No order already carries the job number MO-QUO-2026-011. Pass.

It then creates the order:

```
Manufacturing Order MO-QUO-2026-011
  Product     = Widget-A
  Quantity    = 200
  Due Date    = 09/01/2026   (the customer's requested date)
  Direction   = Forward       (carried from the quote)
  Estimate    = $9,230        (with labor/material split retained)
  Unit Price  = $85.00
  Customer    = Acme Industries
  Status      = Scheduled (created, not yet placed on the calendar)
```

The quote status flips to Converted. Any further attempt to convert QUO-2026-011 is rejected at the first check.

## The order is created, not yet scheduled

Conversion places the order in the Manufacturing Orders list but does not touch the calendar. Your Gantt and work-center load look identical until the next **Drive Schedule** run picks up the new order and slots it in, using the due date as the deadline and the carried direction to reproduce the quoted approach.

This separation is deliberate. It lets a planner convert a batch of approved quotes and then run one scheduling pass, rather than reshuffling the plan on every individual conversion. It also means the promise date the customer received (built by the [quote simulation](/blog/edgebic-quote-simulation-explained)) and the date the real run produces are built by the same engine, so they agree.

## Guarded three ways

Double-conversion is one of the classic ways a shop ends up building the same job twice. EDGEBIC blocks it with three independent guards: the Converted status check, the authoritative link check against existing orders, and the job-number collision check. If any one fires, conversion is refused. If you genuinely need a repeat order, you create a fresh quote or a new Manufacturing Order, which keeps the record trail clean.

## Prepare the quote before you convert

Conversion inherits whatever the quote holds, so the quality of the order depends on the state of the quote at that moment. Two habits make the inherited plan a good one.

First, simulate before converting. A quote that was never simulated carries only a routing estimate, not a capacity-aware plan, so the dates the order inherits would ignore current shop load. Run the simulation so the start and end dates, the cost, and the hours the order inherits are the ones built against real capacity.

Second, set the status to Approved (or any status except Converted) once the customer commits. The status is informational and you can move freely between values, but landing on Approved before conversion keeps the record honest: the order that appears is clearly the result of an accepted quote, not a draft that slipped through. The estimate fields the order carries then feed the later quote-versus-actual variance report, which only means something if the quote it came from was a real, simulated, approved plan.

## Where conversion sits in the bigger flow

Conversion is the hinge between selling the work and building it. Before it, the quote is a what-if: you [simulate the date](/blog/how-edgebic-turns-a-quote-into-a-promise-date), price it, and compare routing options. After it, the order is real and enters the scheduling pipeline. Because the direction and dates carry across, the shop builds what sales sold.
