**To switch a product between make-to-stock and make-to-order in EDGEBIC by User Solutions, edit the product, set the build method in its inventory planning section, and change the stocked flag to match.** Those two settings travel together: a make-to-stock product needs to be marked stocked so inventory postings and netting apply to it. This post is the single task. For the strategy behind the choice, read [make-to-stock vs make-to-order in EDGEBIC](/blog/make-to-stock-vs-make-to-order-in-edgebic).

The inventory planning attributes described here belong to the inventory capability. Availability varies by installation, so check with User Solutions which of these fields your build exposes before planning a catalog-wide change.

## Before you start

- The product exists and has a routing, so the resulting jobs can actually be scheduled.
- You know which direction you are moving. Make-to-stock means the item is built against replenishment triggers and held. Make-to-order means it is built when a customer orders it.
- For a switch to make-to-stock, decide the replenishment numbers in advance: safety stock, reorder method, and the quantities that go with the method you pick.
- Note the current on-hand position for the product. A switch to make-to-stock against zero stock generates suggestions immediately.

## Steps

1. Open the **Product** tab and find the product using the search panel.
2. Click the edit button in the row's **Actions** column.
3. Go to the inventory planning section of the dialog, where the make-to-stock and make-to-order attributes live.
4. Set the **Build Method** to make-to-stock or make-to-order as required.
5. Set the stocked flag to match. Marking a product stocked is what enables inventory netting and receipt and issue posting for it. This step is not optional on a make-to-stock product.
6. For a make-to-stock product, set the replenishment triggers in the same visit:
   - **Safety Stock**, the minimum buffer the projection protects.
   - **Reorder Method**, chosen from none, reorder point, or min/max.
   - **Reorder Level** and **Reorder Quantity** for the reorder point method, or **Min Level** and **Max Level** for min/max.
   - The **Lot Size Rule**, which decides whether a suggestion covers exactly the net requirement or always orders the reorder quantity.
7. Click **Update**.

## What changes when you save

| Setting | Effect after the switch |
|---|---|
| Build method set to make-to-stock | Completed manufacturing orders for the product post a stock receipt, and demand can be satisfied from stock rather than from a fresh job |
| Stocked flag on | Inventory netting and posting apply to this product |
| Reorder method and levels | The projection can raise replenishment suggestions when the projected balance falls below the trigger |
| Lot size rule | Decides the size of each suggestion |
| The schedule | Nothing moves. Build method is not a scheduling input |

The practical difference shows up upstream of the scheduler. A make-to-order product waits for demand to arrive as a customer order. A make-to-stock product is replenished against its own triggers, so the planner reviews suggestions and firms the ones worth building. Once a job exists, the engine schedules it the same way either way, against the same finite work center capacity.

## How to check it worked

1. Re-open the product and confirm both the build method and the stocked flag show the values you set. A mismatched pair is the single most common fault on this task.
2. Run the anomaly checks. A product declared make-to-stock without the stocked flag is a documented integrity fault and shows up there rather than as a visible error on the form.
3. Open the inventory projection for the product and read one full horizon. A make-to-stock product with a reorder method configured should show either a healthy projected balance or a replenishment suggestion where the balance dips below the trigger. See [how to read the projection](/blog/how-to-read-the-projection-in-edgebic).
4. Confirm the suggestion size matches the lot size rule you chose. A fixed order quantity suggestion equal to the reorder quantity is correct; a lot-for-lot suggestion should equal the shortfall.

## Common mistakes

**Changing the build method and leaving the stocked flag alone.** The product then claims to be replenishment-driven while inventory posting is off. The anomaly checks catch it, but only if you look.

**Leaving the reorder method at none.** A make-to-stock product with no reorder method never raises a suggestion. Nothing errors, so it reads as a broken feature rather than an unfinished setup.

**A generous fixed order quantity on a slow mover.** Fixed order quantity always orders the full amount regardless of the shortfall, which builds stock steadily. Start with lot-for-lot until the demand pattern is clear.

**Switching to make-to-order and expecting stock to disappear.** Existing on-hand quantity stays where it is. Only the way future demand is generated changes.
