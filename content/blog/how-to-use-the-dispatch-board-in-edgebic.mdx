**To use the operator dispatch board in EDGEBIC by User Solutions, open the Daily Hours tab and select the Dispatch tab, which shows a read-only per-operator daily work list grouped by operator and date with per-group hour sums.** Set a date window and an operator filter to narrow it, then read or print it. It is the printable answer to who does what and when, drawn from the crew assignments the scheduler generated on its last run. It shows the plan, not a record of who actually worked.

This post covers the operator-grouped board. For the machine-sequenced view, see [how to print a dispatch list for a work center](/blog/how-to-print-a-dispatch-list-for-a-work-center-in-edgebic); the two answer different questions.

## Before You Start

| Prerequisite | Why |
|---|---|
| Operators are certified and rostered | The board shows crew assignments, which only exist for staffed steps |
| A scheduling run has completed | The rows come from the last run's generated assignments |
| You know the window and person you want | The board is filtered by a date window and an operator picker |

## Step 1: Open the Dispatch Tab

Open the **Daily Hours** tab and select the **Dispatch** tab. The board loads a read-only list of planned operator work. It is a reporting surface: it reassigns nothing and reschedules nothing, it presents what the scheduler already decided.

## Step 2: Set the Window and Operator Filter

Set the **From** and **To** dates to the window you care about, a shift or a week. Set the operator filter to one person to print their day, or leave it open for the whole crew. The board recomputes to the filter, so a supervisor handing out schedules can produce one person's list or the full crew's from the same tab.

## Step 3: Read the Grouped List

The board groups the work **Operator** then **Date**, with a per-group hour sum. Each row names the shift, the job, the work center, the operation window, and the hours. Reading top to bottom gives you each person's day in order, which is exactly what a supervisor needs to hand out at shift start.

## Step 4: Print or Hand It Out

Because the list is grouped by person, one print gives each operator their own schedule. On a floor where a certified operator moves between machines through the day, this is the view that tells them where to be and when, in a way a machine-by-machine list cannot.

## What the Dispatch Board Reflects

| Aspect | Behavior |
|---|---|
| Source | Crew assignments generated by the last scheduling run |
| Grouping | Operator then Date, with per-group hour sums |
| Filtering | A date window and an operator picker |
| Freshness | Regenerated wholesale on every run, so it follows the plan |
| Nature | The forward plan, not a record of who actually worked |

The rows are the persisted form of the engine's staffing decisions, which is why they change when the plan changes. How those assignments are produced is described in [how EDGEBIC books operator hours](/blog/how-edgebic-books-operator-hours), and the concept itself is defined in [the dispatch list glossary entry](/blog/glossary-dispatch-list).

## How to Check It Worked

The board shows the expected people for the window, each person's hours sum matches their rostered availability minus any slack, and the jobs listed are the ones scheduled in that window. If a person you expected is missing, they may have no assignments in the window, or the last run did not staff them because they were not qualified or rostered.

## Common Mistakes

- **Treating the board as an actuals record.** It is the plan. Who actually worked comes from kiosk punches, a separate surface.
- **Expecting the same crew every day.** Assignments regenerate each run. Pin a step if a specific person must stay on it.
- **Reading it before a scheduling run.** With no run, there are no assignments to show. Schedule first.
- **Confusing it with the machine dispatch list.** This board groups by person; the work center list groups by machine and sequence.
