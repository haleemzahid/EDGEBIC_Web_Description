**A planned start pin is a durable planner note that fixes the intended start of a not-yet-started operation, without pretending the operation has begun.** It is written by the Gantt's Planned Start Only drag mode, and it records intent rather than fact: no actual dates are written, so the step stays unstarted. On the next scheduling run the engine schedules the pinned step forward from the pinned date. It is the difference between penciling a plan onto the board and clocking in.

This entry is part of the [EDGEBIC by User Solutions](/edgebic) glossary series; for the broader vocabulary of planning, see the [manufacturing glossary](/blog/manufacturing-glossary). To choose the drag behavior that writes one, see [how to change the drag mode on the Gantt](/blog/how-to-change-the-drag-mode-on-the-gantt-in-edgebic).

## How a Planned Start Pin Works

The Gantt's drag has three modes that decide what a dragged bar writes on apply. Two of them write actuals: one records both an actual start and end, the other just an actual start for an in-progress step. The third, Planned Start Only, writes neither. Instead it stamps a durable planned-start date on the operation, a pin that says this is when I intend this step to begin.

Because a pin writes no actuals, the step remains unstarted, and the engine keeps full freedom to schedule around it, with one addition: it schedules the pinned step forward from the pinned date rather than from wherever it would otherwise fall. Downstream steps then follow from the pinned step's new placement.

The pin is durable, so it survives reschedules and keeps steering the step run after run. In the engine's direction-precedence order it sits above backward and plain forward scheduling but below actuals, which means a pin governs an unstarted step, and any real actual dates take over the moment the work actually begins.

## A Concrete Example

A planner wants a finishing operation to plan for Thursday morning. The material will be staged by then, and Thursday is when the finishing cell has a clean run. But nobody has touched the part yet, so recording an actual start would be a lie the schedule would carry forward.

Instead the planner switches the Gantt to Planned Start Only, drags the finishing bar to Thursday morning, and applies. That writes a durable planned start pin and no actuals. On the next run the engine schedules the finishing step forward from Thursday morning, and the steps after it fall into place behind it. It is a plan, penciled on the board, not a punch, and the schedule treats it exactly that way.

## How EDGEBIC Uses It

A planned start pin is written through the Gantt and consumed by the engine:

- **The Planned Start Only drag mode** is the way to create one. Dragging a bar in that mode writes the pin and leaves the step unstarted, distinct from the two drag modes that write actuals.
- **The engine schedules forward from the pin** on every run and re-applies it across reschedules because it is durable, not a one-time move.
- **Actuals outrank the pin.** As soon as the step gets a real actual start, direction precedence hands control to the actuals, and the pin steps aside.

A pin is the intent-side counterpart to an [actual date](/blog/what-is-an-actual-date-in-scheduling), which records fact and freezes the step. Reading the two together clarifies why one steers an unstarted step while the other locks a started one, and [how to change the drag mode on the Gantt](/blog/how-to-change-the-drag-mode-on-the-gantt-in-edgebic) shows how to pick which one a drag writes.
