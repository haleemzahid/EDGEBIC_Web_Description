**To group orders by sales order in EDGEBIC by User Solutions, click the group view toggle on the Orders tab toolbar.** The flat orders grid switches to a tree where each sales order is a top-level row and its manufacturing orders indent beneath it. This gives a demand-centric view of the plan, where you read production the way the customer sees the order. Add, edit, and delete still work through the same dialogs, so only the arrangement changes, not how you manage jobs. Toggle again to return to the flat list.

This is a display task, not a scheduling one. To limit a run to a single sales order, see [how to schedule only the jobs on one sales order](/blog/how-to-schedule-only-the-jobs-on-one-sales-order-in-edgebic). The full task set is on the [EDGEBIC how-to hub](/blog/edgebic-how-to-hub).

## Before You Start

- At least one sales order exists, with manufacturing orders linked to it. Grouping only helps when jobs carry a parent sales order.
- You are on the Orders tab in Drive Schedule, where the toggle lives.
- An understanding that this rearranges the view and does not change scope or scheduling.

## Step by Step

1. Open the **Orders** tab in Drive Schedule.
2. On the toolbar, click the **group view** toggle (the sales-order grouped view mode button).
3. The grid becomes a tree. Each sales order is a parent row; its jobs indent beneath it.
4. Expand or collapse a sales order by clicking its parent row.
5. To act on a job, right-click or select it and use **Edit**, **Delete**, or **Add** as usual.
6. Click the toggle again to return to the flat grid.

## What Changes When You Toggle

The Orders data region swaps the flat grid for a tree control that nests jobs under their sales orders. Jobs with no linked sales order appear ungrouped. The change is purely visual: the same jobs, the same dates, the same actions. Nothing about scheduling scope changes, because scope is controlled by the sales order filter and by which rows you select, not by the grouping. The grouped layout is session-only, so a restart returns the tab to the flat grid.

## How to Check It Worked

After toggling, confirm a sales order you know appears as a parent row with its jobs indented under it. Expand it and count the child jobs against what you expect on that order. Open one child job's edit dialog to confirm actions still route normally. If a job you expected is missing from a sales order, it is probably not linked to that order, which is a data issue rather than a view issue.

## Common Mistakes

- **Expecting it to filter the schedule.** Grouping rearranges the view. Use the sales order filter to narrow what the scheduler acts on.
- **Looking for it to persist.** The grouped view resets on restart. Toggle it on each session if you prefer it.
- **Assuming ungrouped jobs are broken.** A job with no linked sales order simply has nowhere to nest. Link it first if it belongs to an order.
- **Confusing grouping with the customer view.** This groups by sales order, not by customer. To see a customer's history, use the customer view instead.
