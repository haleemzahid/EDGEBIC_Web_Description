**To deactivate a work center in EDGEBIC by User Solutions, open the machine, uncheck Is Active, and save.** It drops out of routing dropdowns and the scheduling engine's available machine list, while every historical schedule that used it stays intact. Deactivation is the reversible, history-preserving way to retire a machine.

Deactivating is not deleting. Deleting is blocked while a machine is in use and throws the record away; deactivating keeps the audit trail and lets the machine come back. This page covers the clean retirement, and the one cleanup step that prevents a scheduling error afterward. For the wider machine model, start with [work centers explained](/blog/edgebic-work-centers-explained).

## Before You Start

- **You know which routings use the machine.** A step still pointing at a deactivated machine will fail at schedule time.
- **You have a replacement or reroute plan** for any live work currently on the machine.
- **You want to keep the history.** If so, deactivate rather than delete.

## Step 1: Open the Work Center for Editing

Open the **Work Centers** area, select the machine, and click **Edit** to open its configuration.

## Step 2: Uncheck Is Active

Uncheck **Is Active**. This marks the machine out of service for scheduling.

## Step 3: Save

Click **Update**. The machine is now inactive: gone from routing dropdowns and from the scheduler's available list, with its history preserved.

## Step 4: Clear the Routing References

Deactivating hides the machine from new selections but does not rewrite existing routings. Find any active routing steps that still point at the machine and reroute them to an active machine or an alternate, then rerun **Drive Schedule**. Doing this prevents the scheduler from hitting a step whose only resource is now out of service.

## What Changes When You Save

| Surface | Effect |
|---|---|
| Routing dropdowns | The machine no longer appears for new steps |
| Scheduling engine | Excludes the machine from the available list |
| Historical schedules | Unchanged and readable |
| A routing step still pointing at the machine | Will fail at the next scheduling run until rerouted |

## Deactivate Versus Delete

| Action | When to use | Effect |
|---|---|---|
| **Deactivate** (uncheck Is Active) | A retired or idle machine you may keep on record | Reversible; history preserved; hidden from new work |
| **Delete** | A record created in error and never used | Blocked while the machine is referenced by any routing, schedule, or override |

The delete guard is deliberate: it refuses to remove a machine that routings, schedules, or overrides still depend on, so you cannot orphan a routing by accident. For anything that has been used, deactivation is the correct path.

## Reactivating a Machine

Deactivation is reversible, which is a large part of why it beats deletion. If a retired machine comes back into service, or a temporarily idle one is needed again, open it, recheck **Is Active**, and save. It rejoins the routing dropdowns and the scheduler's available list, and any routing steps that still reference it start scheduling normally again at the next run. Because the history was never thrown away, the machine's past jobs and the new ones sit on one continuous record. This makes deactivation the right tool for a machine that is out on a long maintenance window, waiting on a rebuild, or idled for a slow season, where a delete would force you to recreate the whole record and lose the trail.

## How to Check It Worked

1. Confirm the machine no longer appears when you add a step to a routing.
2. Run **Drive Schedule** and confirm it completes without an error about a missing or unavailable resource.
3. Open a past schedule that used the machine and confirm the history still reads correctly.
4. If a run errors, find the routing step still pointing at the machine and reroute it.

## Common Mistakes

**Deactivating without clearing routings.** A step that still references the machine fails at schedule time. Reroute active steps first, or immediately after, and rerun.

**Deleting instead of deactivating.** Deletion throws away history and is blocked while the machine is in use. For a real machine that ran real jobs, deactivate.

**Assuming existing bars vanish.** Deactivation stops new work landing on the machine; it does not move bars already placed. Rerun to rebuild the plan without the machine.

**Forgetting the machine can return.** Deactivation is reversible. If the machine comes back, recheck Is Active and it rejoins scheduling.
