**The Work Center Dispatch report in EDGEBIC by User Solutions is the run queue a supervisor prints and hands to each station: it lives in the Reports hub, filters to one work center, and lists every operation whose planned window falls in the range, ordered by planned start.** It is the report that turns a schedule into a piece of paper an operator can work from. Here is how to produce one station's sheet, start to finish.

For the full report catalog this belongs to, see [EDGEBIC reports explained](/blog/edgebic-reports-explained), and for the general concept, [what a dispatch list is](/blog/glossary/dispatch-list). Every task in this library is mapped on the [EDGEBIC how-to hub](/blog/edgebic-how-to-hub).

## Before You Start

- Jobs have been scheduled. The dispatch list reads the plan, so an unscheduled shop dispatches nothing.
- Work centers are active. Every active station appears in the dropdown, even one with nothing booked in the window.
- The date range covers the shift or shifts you are dispatching for.

## Step 1: Open the Report

Open **Reports** from the main navigation and click **Work Center Dispatch** in the **Operational** group. Unlike most reports, the dispatch list carries its filters inline at the top of its own window rather than in a pop-up dialog, so it opens ready to be shaped.

## Step 2: Set the Range

At the top of the report window, set **From** and **To**. The default runs from today through the next 14 days, which is the fortnight view a lot of floors like to see. For a single shift sheet, set both to today.

The range decides which operations qualify: any operation whose planned window overlaps the dates appears, and the rest are held back. Material-only rows never appear at all, because they are not something an operator runs.

## Step 3: Pick the Station

Choose the station in the **Work Center** dropdown. It defaults to all, which shows every station grouped, and it lists every active work center individually even when a station has nothing in the window.

For a printed sheet, pick one station. A single-station export is a queue an operator can hold; an all-stations export is a plant document, useful for planning but not for the floor.

Click **Load**. Each work center group expands automatically, and within a group the rows run in planned-start order, top to bottom.

## Step 4: Read the Columns That Matter on the Floor

The dispatch grid is wide, but an operator works from a handful of columns.

| Column | What it tells the operator |
|---|---|
| **Job No** / **Product** | Which job, and the end product it ships |
| **Seq No** / **Step** | The operation's place in the routing and its description; lower runs first within a job |
| **Setup Hrs** | Changeover time before the run starts |
| **Req Hrs** | Total required run hours, per-unit hours times quantity |
| **Act Hrs** | Hours already logged against this operation |
| **Rem Hrs** | Required minus actual, floored at zero: what is genuinely left |
| **Sched Start** / **Sched End** | The planned window, with time of day |
| **Due Date** | The parent job's due date, the date this queue protects |
| **Priority** | The parent job's priority; higher is more urgent when the operator must choose |
| **Instance** | Which machine instance the operation is booked on |
| **Status** | Completed, In Progress, Ready to Start, or Scheduled |

Rem Hrs is the one to teach. On a job an earlier shift started, it is the only column that tells the truth about how much work remains.

## Step 5: Print It

With the station selected and loaded, click **Export to PDF** in the report window footer and print the result. Export to Excel is there too if the sheet feeds a spreadsheet rather than a clipboard.

Your column layout sticks. Column order, widths, grouping and sorting are saved per report and restored next time, so once you have the dispatch grid arranged the way the floor likes it, every future print matches. Full export mechanics are in [how to export a report to Excel](/blog/how-to-export-a-report-to-excel-in-edgebic).

## What Changes When You Print It

Nothing in the system. The dispatch list is read-only, and printing it does not touch the plan.

What it changes is the floor: it replaces "what should I run next" with a sequence somebody already decided using capacity, due dates and dependencies. The whole point is that the operator does not re-plan; they run the sheet top to bottom and log actuals as they go.

## How to Check It Worked

Read three things before you hand the sheet over. The station name at the top of the group is the one you meant to print. The top row's status is a job that can actually start (Ready to Start or In Progress, not blocked upstream). And the Rem Hrs on any in-progress row looks plausible against how far the job has run. If Rem Hrs equals Req Hrs on a job the floor knows is half done, actuals are not being logged, and the sheet will send an operator to redo finished work.

## Common Mistakes

- **Printing the all-stations view for the floor.** It is a planning document, not a station queue. Filter to one station first.
- **Ignoring Rem Hrs on partial operations.** Req Hrs is the whole operation; Rem Hrs is what is left. Handing an operator Req Hrs on a half-run job overstates the work.
- **Setting too narrow a range and losing the next job.** If the floor works ahead, a today-only range hides tomorrow's queue. Match the range to how far ahead the station runs.
- **Second-guessing the sequence job by job.** The rows are already in run order. Reordering by hand on the floor discards the plan the sequence encodes.
