**To find work centers with no shifts in EDGEBIC by User Solutions, open the work center list and read the shift calendar column: any machine showing the amber custom badge with an empty shift list has no working hours at all.** A work center in that state has zero capacity. It never receives a job, and nothing about the row says so directly.

This is a five minute audit worth running after any import, after any calendar reorganization, and before the first schedule run at a new site. The failure it catches is quiet, which is exactly why it is worth hunting deliberately.

## Before You Start

- **Your shifts exist.** If the plant has no shifts defined at all, every machine has zero capacity and this audit will tell you something you already know. [How to add a second shift in EDGEBIC](/blog/how-to-add-a-second-shift-in-edgebic) covers creating one.
- **You can open the work center list** and edit a work center.
- **You know which machines were deliberately taken off the plant calendar.** Those are the only ones that can fail this test.

## Step 1: Open the Work Center List

Open the **Workcenter** tab. The work center management page lists every resource with columns for the identifier, the name, the number of instances, and the one that matters here: **Shift Calendar**.

## Step 2: Read the Shift Calendar Column

That column shows one of two badges per row:

| Badge | Meaning | Can it have zero hours? |
|---|---|---|
| **Global** (green) | The machine inherits the plant-wide shift definitions | No. It gets every plant shift automatically |
| **Custom** (amber) | The machine follows only the shifts on its own list | Yes, if that list is empty |

Sort or group the grid by this column so the amber rows collect together. On most sites that is a short list, often two or three machines. Those are the only rows you need to open.

## Step 3: Open Each Custom Work Center

For each amber row, click **Edit** and select the **Associated Shifts** tab.

You are looking for one thing: does the list contain at least one shift? An empty list is the fault. The scheduler works through a machine's associated shifts when it looks for a place to put work, so an empty collection means there is nowhere to put anything.

## Step 4: Fix Each Gap

There are two honest fixes, and which one you choose depends on why the machine came off the plant calendar.

**The machine really does run the plant pattern.** Tick **Use Global Shifts** again. The custom list is ignored, the badge flips back to green, and the machine picks up every plant shift. This is the right answer when somebody unticked the box while exploring and never put it back.

**The machine genuinely runs its own hours.** Leave global shifts off and add the shifts it actually works, either by adding an existing shift or by creating one that belongs to this machine. [How to give one work center its own calendar in EDGEBIC](/blog/how-to-give-one-work-center-its-own-calendar-in-edgebic) walks that dialog in full.

Save the work center.

## Step 5: Check Two Neighbors of the Same Symptom

While you are in the record, confirm two fields that produce an identical zero-capacity result:

- **Is Available.** Unticked, the scheduler skips the work center entirely.
- **Effective Date.** Set in the future, the machine is treated as unavailable until that date arrives. It is meant for equipment not yet commissioned, and it produces a silent zero-capacity resource when used by accident.

## How to Check It Worked

1. **The badge tells the truth.** A machine you returned to the plant calendar shows the green global badge; a machine with its own calendar keeps the amber badge and now has shifts in its list.
2. **Capacity appears on a date.** Open the work center's capacity view for a normal working day and confirm the hours are no longer zero.
3. **The schedule uses it.** Run the scheduler and look for bars on that machine. A work center that had no calendar yesterday should now be carrying the work it was routed.

## Common Mistakes

**Assuming green badges need checking.** They do not. A global work center cannot have an empty calendar, because it inherits the plant definitions. Spend your time on the amber ones.

**Adding a shift to the plant and expecting a custom machine to get it.** It will not. That is the whole point of a custom calendar: global shift changes do not apply to it. Every new shift a custom machine should work must be added to its own list.

**Reading zero capacity as a scheduling bug.** Nine times out of ten it is a calendar gap, an unticked availability flag, or a future effective date. Check the master data before the engine.

**Deactivating a shift and moving on.** The assignment records stay behind on the work centers that used it, so a machine can look configured while contributing fewer hours than it did the day before. Deactivating a shift is worth a follow-up pass over the machines that used it.
