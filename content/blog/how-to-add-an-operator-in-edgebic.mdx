**To add an operator in EDGEBIC by User Solutions, open the Daily Hours tab, select the Operators inner tab, click Add Operator, and fill in the operator's name, badge code, and Active status.** The person appears in the operator list ready to be certified in skills and rostered onto shifts. Adding the operator is the first of three moves: the record does nothing on its own until the person holds a skill and is rostered onto a shift.

This post covers creating the operator record. The full setup arc, from skills through rosters to routing steps, is walked end to end in [how to set up operators, skills, and rosters](/blog/how-to-set-up-operators-skills-and-rosters-in-edgebic).

## Before You Start

| Prerequisite | Why |
|---|---|
| You know the person's badge or payroll code | The Code is a required field and a stable key for imports and reports |
| You know which skills they will eventually hold | Certifying comes right after adding, and it is what makes the operator schedulable |
| Global shifts exist | The roster keys on global shifts, so the person can only be rostered once shifts are defined |

## Step 1: Open the Operators Tab

Open the **Daily Hours** tab from the main navigation and select the **Operators** inner tab. This is the operators manager: the operator list on the left, and detail sub-tabs on the right for the selected person's skills, roster, and time off. Everything about a single operator is edited here.

## Step 2: Open the Add Operator Dialog

Click **Add Operator**. The **Add Operator** dialog opens with the fields for a new person.

## Step 3: Fill In the Operator Fields

| Field | Required | What it does |
|---|---|---|
| **Operator Name** | Yes | The display name used everywhere in the app, for example Joe Alvarez |
| **Code** | Yes | The badge or payroll code, for example JA-01, used as a stable key for imports and reports |
| **Notes** | No | Free text, for example a note about night-shift availability |
| **Status: Active** | Set | Checked means schedulable; unchecked means the person drops out of scheduling but stays for history |

Use the Code your existing systems already know the person by. It is what an import file matches on, so aligning it with your payroll or badge numbers now saves reconciliation later.

## Step 4: Save

Click **Save**. The operator appears in the list with a person icon. Repeat for the rest of the crew. At this point each person exists as a record but is not yet schedulable, because they hold no certifications and cover no shifts.

## What Changes When You Save

| Surface | Effect |
|---|---|
| The operator list | Gains the new person, selectable for detail editing |
| Scheduling | Nothing yet: an operator with no skill and no roster is inert |
| Reporting | The person is available as a name and code for dispatch and calendar views once they carry assignments |

Creating the operator moves no jobs. The scheduler only begins to care about a person once a routing step requires a skill they hold and they are rostered onto a shift with hours. That mechanism is described in [operator and skill scheduling explained](/blog/edgebic-operator-and-skill-scheduling-explained).

## How to Check It Worked

The new operator appears in the list with the person icon, and selecting them shows empty Skills, Roster, and Time Off sub-tabs ready to fill. If the person does not appear, confirm you saved rather than closing the dialog. The real proof of a working operator comes later: after certifying and rostering them, they show up in the qualified pool for their skill and can be staffed to a step.

## Common Mistakes

- **Stopping after Add.** An operator with no certification and no roster changes nothing in the schedule. Add, then certify, then roster.
- **Inventing a Code that does not match payroll.** The Code is the import and reporting key. A code that disagrees with your existing systems creates reconciliation work.
- **Deleting instead of deactivating.** People who have left should have Active unchecked so history survives. Delete is reserved for records created in error.
- **Expecting the schedule to move on save.** Adding a person is master data. Work only re-staffs on the next scheduling run, and only if the person is qualified and rostered.
