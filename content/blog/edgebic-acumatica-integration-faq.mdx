**These are the questions Acumatica manufacturers ask in the first conversation, answered without hedging: there is no connector, the interface is your Generic Inquiry exports, nothing is deployed in the tenant, and nothing you import can disturb an order already running.** Each answer stands on its own, so skip to whichever one you came for.

EDGEBIC by User Solutions is a finite capacity scheduling platform that sits beside your ERP. The full walkthrough is the [complete Acumatica integration guide](/blog/edgebic-acumatica-integration-guide), and the field-level detail is in the [Acumatica to EDGEBIC mapping reference](/blog/acumatica-to-edgebic-data-mapping-reference).

## Does EDGEBIC connect through the Acumatica API?

No, and that is deliberate. EDGEBIC integrates through reusable import masks that read Excel, CSV, delimited text, or a database source. You map your export's columns onto EDGEBIC's fields once and save the mask; every later run is two clicks. Because there is no API integration, there is no package in the tenant, no integration credential, no endpoint to register, and nothing to version-match when the platform updates on its own schedule. A connector is a dependency. A Generic Inquiry export is not.

## Does EDGEBIC replace Acumatica?

No. Acumatica stays the cloud system of record for orders, inventory, purchasing, and financials. EDGEBIC reads exports, builds a finite capacity schedule against real shift hours and real machine counts, and hands back dates and dispatch lists as Excel files. Nothing about how your team uses Acumatica changes. The general case for the split is in [why ERP needs a scheduling add-on](/erp-scheduling-add-on).

## What exactly has to come out of Acumatica?

Four exports carry a complete scheduling model, and a fifth is optional. Stock items (an identifier is the only mandatory column). Work centers (an identifier, plus capacity detail). BOM operations (end product, step name, an operation flag, and hours per unit). Open production orders (item, quantity, and a date). Optionally, labor (job number, work center, date, and hours or pieces). A Generic Inquiry that exports to Excel or CSV is the natural source for each.

## Why use a Generic Inquiry rather than a canned report?

Because a GI shapes the data before the file is written. It can join across tables, filter to open orders only, and present exactly the columns EDGEBIC needs, so the export is already clean. Build one GI per entity, export each to a file, and map the columns once. The GI then feeds the same export every week without change, and because unmapped columns are ignored, adding a column to a GI later never breaks a mask.

## Our times come out in minutes. Do we convert them by hand?

No. Set a conversion factor of `0.016667` on the setup or run column in the operations mask and a 30-minute cell lands as 0.5 hours. Seconds use `0.000278`, and a time quoted per 100 pieces uses `0.01`. The factor is stored on the mask, so every future import converts identically without anyone remembering to do it, and the per-run log records every row if you want to audit the math.

## How long until the first real schedule?

Most shops see a first finite capacity schedule from their own data in the first working session, and a tuned one within the week. The documented benchmark in the User Solutions lineage is the Plastilite integration on Fourth Shift: 5 days, Monday to Friday, from first export to a complete optimized schedule with dates synchronized back to the ERP. That figure belongs to that case rather than being a promise, but the method is what repeats: export, map, import, schedule, tune.

## Do we have to clean our BOMs and routings first?

No, and the attempt usually costs a month. Import what Acumatica holds today, schedule it, and compare the dates with what your planner believes. The disagreements are your defect list and they arrive specific: a wrong hours-per-unit shows up as a job finishing implausibly early, a missing setup time shows up as a machine that changes over for free. Because a routing re-import wipes and recreates that item's steps, each corrected file replaces the last cleanly.

## Do imported production orders schedule themselves?

No, and the separation is deliberate. An import changes data; the scheduler changes the plan. Imported orders appear as unscheduled demand until you run the scheduler, and before the run starts a confirmation states the scope in plain numbers: how many jobs are new and how many existing jobs are being rescheduled. You always know the blast radius before anything moves.

## Can an import disturb orders already running?

No, for two independent reasons. Every scheduled job carries a frozen snapshot of the routing it was planned with, so a routing re-import affects future jobs and leaves work in progress alone. And recorded work is never moved by any run: an operation with an actual start and an actual end is historical fact, and no reschedule, mode, or setting will shift it.

## We model a work center as one resource in Acumatica. How does EDGEBIC handle several identical machines?

Through the machine-count column on the work center file. This is the single column cloud ERP exports most often leave out, because a work center is usually one record with a capacity figure. Fill the instance count deliberately for every multi-machine center: a cell of four machines imported as one produces a plan roughly four times too long, and it fails quietly, since nothing errors and the dates are simply wrong. The arithmetic is in [how EDGEBIC calculates work center capacity](/blog/how-edgebic-calculates-work-center-capacity).

## Can we automate the export and the import?

Partly, and it is worth being precise about which half. The export side automates well: a scheduled GI export that lands a file in a known folder removes the only manual step that ever gets forgotten. The import side stays a deliberate act, because the result dialog exists to be read. A run that reports 40 unexpected Failed rows is information a person needs to see before the schedule is built on top of it. Most shops settle on automated exports plus a two-minute human import.

## What can import never bring across?

The settings that most change what a schedule looks like, because no ERP export has a column for them. Work center groups (machine pools re-shopped on every reschedule, with per-member efficiency factors). The sequence-dependent setup matrix that lets the optimizer sequence work to cut changeover. Operator skills and rosters. Bottleneck anchoring. Lot streaming with transfer batches. Each is configured once inside EDGEBIC and then applies to every imported order afterwards. The [EDGEBIC product overview](/edgebic) maps them and the [ERP integration hub](/edgebic-erp-integration) explains where the import boundary sits.

## Who runs this day to day?

The planner, in about twenty minutes each morning, without IT. Involve IT exactly once, to make the five Generic Inquiries with stable columns exporting to a known folder. After that the routine is export, run the saved masks, run the scheduler, publish the dispatch lists.
