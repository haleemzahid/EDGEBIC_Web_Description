**To change the drag mode on the EDGEBIC Gantt, use the Drag writes selector on the Schedule View toolbar before you move a bar: Actual Start & End records that the work ran there, Actual Start records only that it began there, and Planned Start writes a future pin with no actuals.** The selector decides what a saved drag records, which is the single most important choice on this screen in EDGEBIC by User Solutions, because the wrong mode records fiction.

This post covers the one task. For the whole drag-and-save workflow it sits inside, read [drag and drop rescheduling in EDGEBIC](/blog/drag-and-drop-rescheduling-in-edgebic); the full task library is at the [EDGEBIC how-to hub](/blog/edgebic-how-to-hub).

## Before You Start

- At least one job is scheduled and drawing on the Schedule View Gantt.
- You know what actually happened to the operation you are about to move: it ran, it started, or it is still only planned.
- You understand the rule of thumb: past uses Actual Start & End, running uses Actual Start, future uses Planned Start.

## The Steps

1. **Open the Schedule View** so the scheduler Gantt is showing.
2. **Find the Drag writes selector** on the toolbar.
3. **Pick the mode that matches reality:**
   - **Actual Start & End**: the work physically ran at the new time. This is the default.
   - **Actual Start**: the work began at the new time and is still running; the end stays open.
   - **Planned Start**: nothing has happened yet; you want the operation to run there in future.
4. **Drag the bar** to its new time slot, or onto a different work center's lane.
5. **Click Save Changes.** The drag records exactly what the selected mode says.

## What Changes When You Save

| Mode | What the save records | Resulting bar state |
|---|---|---|
| Actual Start & End | Actual start and actual end on the new dates | Applied |
| Actual Start | Actual start only, end left open | Actual Start Applied |
| Planned Start | A durable planned-start pin, no actuals | Planned Applied |

Whatever the mode, the engine's original scheduled dates are kept alongside what the drag writes, so EDGEBIC always knows plan versus reality. A **Planned Start** pin has one extra property worth knowing: on the next reschedule the engine treats it like an actual start and locks the operation to that date and work center, and the pin dissolves automatically the moment a real actual start is logged. To hold a segment exactly where it sits without writing any dates at all, [lock the operation in place](/blog/how-to-lock-an-operation-in-place-on-the-edgebic-gantt) instead of pinning it.

## How to Check It Worked

After you save, read the bar's state color against the legend. Actual Start & End turns the bar to Applied, Actual Start turns it to Actual Start Applied (in progress), and Planned Start turns it to Planned Applied. If you meant to plan a future operation but the bar shows Applied, you saved with the wrong mode; right-click the bar and clear its actuals, switch the selector to Planned Start, and redo the drag.

## Common Mistakes

**Leaving the selector on the default and dragging a future operation.** Actual Start & End tells EDGEBIC the work already happened at that future date. That skews progress and on-time figures. Switch to Planned Start for anything that has not begun.

**Marking a start but closing the operation.** If a supervisor is confirming that work began, Actual Start & End writes an end too and closes it. Use Actual Start so the end stays open and the operation reads as in progress.

**Selecting the mode after the drag.** The selector governs the next saved drag, not the last one. Pick the mode first, then drag.

**Expecting a Planned Start pin to be permanent.** It is a plan, not a fact. As soon as a real actual start is logged for that operation, the pin drops out and the actual takes over.
