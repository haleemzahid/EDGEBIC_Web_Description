**To set an operator pin in EDGEBIC by User Solutions, set the routing step's Operator picker to a named person, or drag the operation onto that person's lane on the Schedule View Gantt.** The picker is enabled only once the step has a Required Skill, and it lists only operators qualified for that skill. Once pinned, the step schedules only for that person: the rest of the qualified pool is never a fallback, so the pinned person's absence becomes visible schedule movement rather than a silent substitution.

An operator pin is a planner-side assignment, not a kiosk login. The shop floor kiosk has no login or PIN at all. This post covers the planner mechanism; the wider labor model behind it is [operator and skill scheduling explained](/blog/edgebic-operator-and-skill-scheduling-explained).

## Before You Start

| Prerequisite | Why |
|---|---|
| The step has a Required Skill set | The Operator picker is enabled only once a skill is set |
| The person you want to pin is certified in that skill | The picker lists only qualified operators |
| You accept the trade-off | A pin trades schedule flexibility for certainty about who does the work |

## Step 1: Confirm the Step Requires a Skill

Open the **BOR** tab and select the step, or use the BOR Designer's properties panel. Confirm **Required Skill** is set. A pin without a skill is meaningless, so the Operator picker stays disabled until a skill is chosen. If you have not set one yet, do that first, which is covered in [how to require a skill on a routing step](/blog/how-to-require-a-skill-on-a-routing-step-in-edgebic).

## Step 2: Set the Operator Picker

Set the step's **Operator** field to the named person. The list shows only operators qualified for the step's skill, so you cannot accidentally pin an uncertified person. Leaving the field on **Auto** lets the scheduler staff the least-loaded qualified person, which is the right default for most work.

## Step 3: Or Pin by Dragging on the Gantt

Alternatively, on the Schedule View with **View by** set to **Operator**, drag the operation's bar onto the target person's lane. The drop is accepted only if that person is qualified for the step's skill; an unqualified drop snaps back with the reason. Dropping on the **Unassigned** lane clears the pin. This is the same pin, set from the Gantt instead of the picker.

## Step 4: Reschedule

The pin is stored when you set it, including with the job's preserved routing so it survives reschedules. Run **Drive Schedule** or a reschedule to see the effect. From then on, only that person's hours count for the step.

## What Changes When You Pin

| Surface | Effect |
|---|---|
| The step's staffing | Only the pinned person's hours are considered; the rest of the pool is never a fallback |
| The person's absence | The step slides through their time off to their first day back, not to a colleague |
| A skill change on the step | Keeps the pin; if the person does not hold the new skill, the next run stops with a message naming the problem |
| Clearing the skill | Also clears the pin |

The pin is stored in two places, the global routing and the job's preserved snapshot, so a reschedule that reads the snapshot does not silently drop it. Why the schedule reacts to any labor change only on the next run is described in [how EDGEBIC books operator hours](/blog/how-edgebic-books-operator-hours).

## How to Check It Worked

The step's Operator field shows the named person, and on the Gantt the bar sits in that operator's lane. After a reschedule, the crew line in the bar's tooltip names only the pinned person. If the pinned person is out, the step visibly slides to their return rather than moving to a qualified colleague, which is the pin doing its job.

## Common Mistakes

- **Confusing the pin with a kiosk login.** The kiosk has no login. The pin is a planner-side assignment of a step to a person.
- **Pinning everything.** A pin removes flexibility. Reserve it for steps where the identity of the person is a real requirement, and leave the rest on Auto.
- **Changing a pinned step's skill and expecting the pin to update.** The pin survives the change. If the person is no longer qualified, the next run stops with a naming message.
- **Expecting a pinned step to fall back during a vacation.** It never does. Un-pin to Auto or drag to Unassigned if a substitute is acceptable.
