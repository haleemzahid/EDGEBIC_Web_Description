**A setup sub-phase is one timed stage inside a single changeover, TearDown, Fixture, Tools, FirstArticle, QAHold, or RunOff, recorded separately so a shop can see exactly where its setup minutes go.** Instead of a lone setup number, you get a stage-by-stage timeline of the changeover, which is what makes real setup reduction possible.

## How it works

A changeover is captured as a Setup punch, and that punch can be decomposed into sub-phases, each its own row timed on its own. The sub-phases are sequential and append-only, meaning they are recorded in order and never rewritten, so the changeover reads as a clean timeline.

The standard order is: TearDown, removing the previous tooling and clearing the machine; Fixture, installing the fixture or pallet for the new job; Tools, loading cutting tools, programs, and offsets; FirstArticle, running the first piece and measuring it; QAHold, waiting for a quality inspector to sign off; and RunOff, a production trial before the job reaches full rate.

Each stage carries its own duration, which is the point. Variance analysis needs the split, because the whole reason setups run long is usually concentrated in one or two stages, not spread evenly. Timing every stage turns a fuzzy "setup took a while" into a precise account you can act on.

## A concrete example

Think of a pit stop broken into jobs: the crew jacks the car, one changes each tire, one refuels, one cleans the visor, and the driver waits for the lollipop. Nobody measures the pit stop as a single blur; each job is timed, because that is how you find the crew member to coach. A setup sub-phase does the same for a machine changeover.

Take a CNC changeover that takes 60 minutes. Logged as sub-phases, it reads: TearDown 6 minutes, Fixture 8 minutes, Tools 10 minutes, FirstArticle 5 minutes, QAHold 26 minutes, RunOff 5 minutes. The mechanical work is quick; the 26-minute QA hold is the changeover. That single line tells you the fix is getting an inspector to the machine faster, not drilling the operators on fixturing. Without the split, you would only know the changeover was an hour.

## How EDGEBIC uses it

In EDGEBIC, each setup sub-phase is captured as its own production punch tagged as Setup, with the sub-phase recorded on it, so the changeover is stored as an ordered series rather than a single lump of time. That series feeds variance analysis: the shop can compare how long each stage takes across jobs and machines and find the stage that consistently dominates.

The practical payoff is targeted setup reduction. Because the biggest stage is visible, improvement effort goes where the minutes actually are, whether that is pre-staging tools, standardizing fixtures, or scheduling inspections so a QA hold never stalls a machine. Feeding real setup times back also sharpens the sequence-dependent setup planning, so the plan reflects how long changeovers truly take.
