**To start a scenario on a specific date in EDGEBIC, open the quote's Scenarios view, tick Custom Start Date in the Production Settings group, set the Start Date, then click Save Changes and Run Simulation.** The scenario simulates the job beginning on that date instead of the quote's date. Nothing on the real schedule changes.

A scenario in EDGEBIC by User Solutions is a named what-if variant of a quote's simulation. Custom Start Date is the lever for testing "what if the job could not start until a certain day," most often because raw material or a purchased component arrives then. Setting the start date honestly is what keeps a quoted delivery date truthful when procurement, not capacity, gates the job.

## Before You Start

- **A quote exists and has been simulated once.** Scenarios are children of a quote, and the base simulation is your comparison baseline. See [how to create a what-if scenario](/blog/how-to-create-a-what-if-scenario-in-edgebic).
- **You know the real earliest start.** Usually the material arrival date or a machine availability date.
- **You remember scenarios run forward.** They start at the scenario's start date and report the finish. A backward quote's framing does not carry into its scenarios.
- **You keep a baseline scenario.** A default-start Standard scenario is what you compare against.

## Step 1: Open the Scenario View

On the **Quote** tab, select the quote and click **Scenarios**. The What-If Scenario Analysis view opens. Select an existing scenario or click **Create New Scenario** and name it after the lever, for example `Start after steel arrives`.

## Step 2: Find the Production Settings Group

On the **Scenario Parameters** tab, locate the **Production Settings** group.

## Step 3: Tick Custom Start Date and Set the Date

Tick **Custom Start Date**, then set **Start Date**:

| Field | Effect |
|---|---|
| **Custom Start Date** | Enables the scenario's own start date instead of the quote's |
| **Start Date** | The date the simulation begins when the checkbox above is ticked |

Set **Start Date** to the true earliest start, for example the day raw material arrives.

## Step 4: Save and Simulate

Click **Save Changes**, then **Run Simulation**. Read the **Simulation Results**: **Estimated Start Date**, **Estimated End Date**, **Lead Time**, **Total Hours**, and **Estimated Cost**. Each run overwrites this scenario's stored results, and nothing touches the shop plan.

## What Changes When You Save

| Action | What changes | What does NOT change |
|---|---|---|
| **Save Changes** | The scenario's stored parameters | The quote, the schedule, any real job |
| **Run Simulation** | The scenario's stored dates, hours, and cost | The production schedule |

## How to Check It Worked

1. Confirm **Custom Start Date** is ticked and **Start Date** shows the day you chose.
2. Click **Run Simulation** and confirm **Estimated Start Date** matches your date, not today.
3. Compare the **Estimated End Date** against the customer's wanted date by hand, since the scenario runs forward and will not right-align to a due date.
4. Open the **Comparison Analysis** tab, tick this scenario and a default-start baseline, and read the Lead Time chart.

## Common Mistakes

**Leaving a start date in the past.** A past start lets the simulation consume elapsed capacity and finish unrealistically early. Set it to the true earliest start.

**Forgetting scenarios run forward.** For a finish-by promise, judge the scenario by its Estimated End Date against the customer date; it will not schedule backward.

**Not ticking the checkbox.** The Start Date only takes effect when Custom Start Date is ticked.

**Forgetting to save before simulating.** Save Changes stores the settings, and Run Simulation applies them.
