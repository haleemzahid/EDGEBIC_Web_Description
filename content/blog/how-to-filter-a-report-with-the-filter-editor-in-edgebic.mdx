**The Filter Editor in EDGEBIC by User Solutions builds multi-condition filters on any report grid: right-click a column header, choose Filter Editor, add conditions, and combine them with and or or.** It is how a sixty row report becomes the six rows you can act on this morning. Here is the task, including the part most people get caught by, which is that filters do not persist.

Every task in this library is mapped on the [EDGEBIC how-to hub](/blog/edgebic-how-to-hub). For the report catalog itself, start with [how to run the scheduler anomalies report](/blog/how-to-run-the-scheduler-anomalies-report-in-edgebic).

## Before You Start

- The report is open and has returned rows.
- You know the question. A filter is an answer to a specific question, and building one without a question in mind produces a smaller list that is no more useful.
- You accept that the filter is temporary. It lives for this dialog session only.

## Step 1: Open the Filter Editor

Right-click any column header in the report grid and choose **Filter Editor**. It does not matter which column you right-click, because the editor lets you build conditions on any of them.

## Step 2: Build the Expression

Add a condition by picking a column, an operator, and a value. Add more conditions and combine them.

| You want | Build |
|---|---|
| Critical over-utilization rows only | Check equals U1 and Severity equals Critical |
| One customer's late jobs | Customer equals Acme and Days Late greater than 0 |
| Two work centers | Work Center equals Mill-1 or Work Center equals Mill-2 |
| Everything except one product | Product does not equal Bracket |

Conditions can be nested into groups, so you can express "this customer, and either of these two stations" without splitting it into two runs.

Click **OK** to apply.

## Step 3: Read the Filter Panel

The active filter appears in a panel at the bottom of the grid. Three things live there.

1. **The expression itself**, in readable form. Check it says what you meant.
2. **A toggle** to switch the filter off without losing it, useful for comparing filtered and unfiltered counts.
3. **A close button** to clear the filter entirely.

Always read the panel after applying. It is the fastest way to catch an or where you meant an and, which is the single most common filter error and produces a list that is larger rather than smaller.

## Step 4: Combine With Grouping and Sorting

Filter to the scope first, then group inside it. Filtering to one customer and grouping by work center answers "where is this customer's work sitting" in one screen. Grouping is covered in [how to group a report grid by a column](/blog/how-to-group-a-report-grid-by-a-column-in-edgebic).

Sorting works normally on the filtered set.

## Step 5: Export if You Need to Keep It

Because filters are not persisted, the export is how a filtered result survives closing the report. Put the filter scope in the file name so nobody reads a subset as a total. Method in [how to export a report to PDF](/blog/how-to-export-a-report-to-pdf-in-edgebic).

## Step 6: Clear It

Click the close button in the filter panel. The full result returns. Do this before handing the screen to someone else, because a filtered grid looks identical to an unfiltered one apart from the panel most people do not read.

## How to Check It Worked

- **The row count dropped, and by a sensible amount.** A filter that removes nothing is not matching. A filter that removes everything usually has a typo in a text value.
- **The panel expression matches your intent.** Read it as a sentence.
- **Spot-check one row.** Pick a visible row and confirm it genuinely satisfies every condition.
- **Toggle the filter off and on.** The counts before and after tell you exactly what the filter is doing.

## Common Mistakes

- **Using or where you meant and.** Or widens, and narrows. A filter that returns more rows than the unfiltered report is impossible, but one that returns almost all of them is usually this.
- **Exact text matching on free-text columns.** A trailing space or different capitalization means no match. Prefer contains over equals on descriptions and notes.
- **Expecting the filter to survive a re-run.** It will not. Rebuild it, or export before closing.
- **Sharing a filtered screenshot without saying it is filtered.** Say it in the file name and in the message.
