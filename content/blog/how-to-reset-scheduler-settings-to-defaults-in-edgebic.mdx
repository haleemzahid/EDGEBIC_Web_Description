**To reset scheduler settings to factory defaults in EDGEBIC by User Solutions, open the Schedule configuration panel in Settings and click Reset to Defaults, then confirm.** Every display option returns to its out-of-the-box state and is saved immediately, and the Gantt reloads its work center resources.

This is a display reset, not a scheduling reset. It is the fastest way out of a configuration somebody has experimented into an unreadable state. If your problem is a grid that has lost its columns rather than the scheduler view, see [how to restore a default grid layout](/blog/how-to-restore-a-default-grid-layout-in-edgebic) instead.

## Before You Start

- You have the Settings permission. The Settings tab is hidden otherwise.
- You have exported the current configuration if any of it is worth keeping. The reset overwrites and saves in one action with no undo, and an export is one click.
- You understand the scope: this changes how the plan looks, never what the plan says.

## Resetting the Configuration

1. Open the **Settings** tab and go to the **Schedule** configuration panel.
2. Scroll to the footer buttons: **Reset to Defaults**, **Import**, **Export**, and **Save and Apply Now Configuration**.
3. If you want a safety net, click **Export** first and save the file somewhere you can find it.
4. Click **Reset to Defaults**.
5. A confirmation asks whether you are sure you want to reset all configuration settings. Click **Yes**.

There is no separate save step afterward. The reset applies the factory settings to the live view and saves them as your default in the same action.

## What the Reset Actually Covers

| Area | Returns to |
|---|---|
| Operation state colors | The factory palette for each schedule state |
| Enabled view types | The default set in the view switcher |
| Bar label patterns | The default operation-description pattern, per work center |
| Drag and update behavior | The out-of-the-box settings |
| Actual-date tracking display | Factory defaults for the overlay and variance colors |
| Work center resources on the Gantt | Reloaded from the current work center list |
| Jobs, dates, capacity, actuals | Nothing. These are not configuration |
| Scheduling policy | Not part of this panel. Policy is separate and site-wide |

That last row matters. The scheduler configuration panel is display and interaction; the scheduling policy that governs how the engine behaves is a different setting and is not touched by this reset. See [how to configure scheduling policy](/blog/how-to-configure-scheduling-policy-in-edgebic) if that is what you are actually chasing.

## How to Check It Worked

Go back to the Gantt. Bars should be in the standard colors, all the default view types should be selectable in the view switcher, and bar labels should show the default pattern rather than any custom one that was in place.

Run no schedule to check this. If jobs have moved, something other than the reset caused it, because a configuration reset does not re-plan.

## Recovering a Configuration You Wanted to Keep

If you reset and then discover the previous settings mattered, you have two routes back, both of which depend on preparation:

- **Import a file.** If you exported before resetting (or at any earlier point), click **Import**, pick the file, review the settings, then click **Save and Apply Now Configuration** to persist them. An imported configuration is not saved to the database until you apply and save it.
- **Load a named configuration.** If you had previously saved a named configuration, select it from the available configurations list and load it.

If you have neither, the settings are gone and rebuilding by hand is the only option. That is the whole argument for exporting once your configuration is tuned: a reinstall, a new machine, or a colleague's workstation can then import the file instead of re-clicking every option.

## A Quick Worked Example

A planner spends an afternoon experimenting with the schedule display: he disables several view types, recolors four operation states, and rewrites the bar-label pattern for two work centers. By Friday the board is unreadable to everyone else at the stand-up.

He opens **Settings → Schedule**, clicks **Export** to capture what he built in case one of the color choices was actually good, then clicks **Reset to Defaults** and confirms. The Gantt reloads in factory colors with every view type back in the switcher and standard bar labels. The following Monday, he reintroduces one change deliberately, [changing the Gantt color coding](/blog/how-to-change-the-gantt-color-coding-in-edgebic) for the single state he genuinely wanted to highlight, and exports again so the plant can share it.

## Common Mistakes

**Resetting without exporting first.** The action overwrites and saves in the same step. Thirty seconds of export saves an afternoon of rebuilding.

**Expecting the reset to fix a scheduling problem.** If a job is landing in the wrong week, configuration is not the cause. Look at capacity, calendars, and the routing instead.

**Assuming the reset is plant-wide.** Scheduler configuration is per user. Resetting your view does not fix a colleague's, and their custom colors are still theirs.

**Confusing this with the Clear Data tool.** The main toolbar's reset button opens the Clear Data Tables dialog, which permanently removes rows. That is a different, destructive action. Read the dialog title before you confirm anything: a display reset never asks you to type a confirmation word.

**Forgetting to apply after an import.** An imported configuration sits in the panel until you click **Save and Apply Now Configuration**. Close the panel first and it is lost.
