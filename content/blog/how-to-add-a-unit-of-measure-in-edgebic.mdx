**To add a unit of measure in EDGEBIC by User Solutions, open the units of measure list from Settings, click New, enter a Name and a Symbol, tick the active flag, and click Save.** The new unit appears at once in the product form's Unit of Measure dropdown. It is a two-minute task worth doing before any catalog import, because import does not create the lookups a spreadsheet refers to. For the full product screen, see [how to set up products in EDGEBIC](/blog/how-to-set-up-products-in-edgebic).

## Before you start

- You know which units your catalog actually needs. Most discrete shops need each, one weight unit, and one length unit.
- You have both parts of each unit ready: the descriptive name and the short symbol.
- You have checked the existing list. Duplicated units are the fastest way to make two comparable products look different.
- If a product import is coming, do this first. Import resolves references to lookups; it does not create them.

## Steps

1. Open the units of measure list. It is reached from **Settings**, and is also available from the Products area in some builds.
2. Click **New**.
3. Enter the **Name**, the full descriptive label. For example, `Kilogram`.
4. Enter the **Symbol**, the short form shown in grids and on shop-floor screens. For example, `kg`.
5. Tick the active flag so the unit appears in the dropdown for new products. It is on by default.
6. Click **Save**.
7. Repeat for each remaining unit, then close the list.

## What changes when you save

| Surface | Effect |
|---|---|
| Product dialog **Unit of Measure** dropdown | New unit selectable at once |
| Product grid **Unit** column | Shows the symbol for products assigned to the unit |
| Work center and routing dropdowns that reference units | Pick up the new entry |
| Reports and shop-floor screens | Display the symbol rather than the long name |
| The schedule | Nothing moves. Units are descriptive, not a scheduling input |

Assigning the unit to a product is a separate step on the product record. Open the product, choose the unit from the **Unit of Measure** dropdown, and save. Products carried over from an older system may hold their unit as free text instead. The display falls back to that text when no structured unit is assigned, so a half-migrated catalog still reads correctly while you work through it.

## How to check it worked

1. Re-open the units of measure list and confirm the new row shows both the name and the symbol.
2. Open any product with the edit button and check the **Unit of Measure** dropdown. The new unit should be listed.
3. Assign the unit to one product, save, and confirm the symbol appears in that row's **Unit** column on the product grid.
4. If your installation uses the kiosk, confirm the symbol reads correctly there too. That is the screen with the least room for a long name.

## Common mistakes

**Creating near-duplicates.** `kg` and `Kg` and `kilo` as three separate units split one material family three ways in every report. Search the list before adding.

**Expecting conversion.** There is none. Weight entered against one unit is not translated into another, so a plant that mixes pounds and kilograms produces totals that mean nothing. Pick one unit per measurement type and hold to it.

**Clearing legacy unit text too early.** During a migration, some surfaces still read the old free-text value. Assign the structured unit first, confirm every report and importer that matters is reading the lookup, and only then clear the text.

**Adding units before you have a product that needs them.** A long lookup list slows every dropdown decision. Add units on demand.
