**Where inventory tracking is in use, EDGEBIC by User Solutions can produce a stock on hand report from the Reports hub: a point-in-time snapshot of every stocked part with its current on-hand, cost, value, safety stock, and reorder level, sorted shortages first.** It answers "what do we have on the shelf right now, and what is running short", straight from the inventory ledger.

This report reads the same ledger that the [inventory ledger audit](/blog/how-to-audit-the-inventory-ledger-for-a-part-in-edgebic) drills into for a single part, and it pairs with [projected stock](/blog/how-to-check-projected-stock-for-a-part-in-edgebic) for the forward view. Every task in this library is mapped on the [EDGEBIC how-to hub](/blog/edgebic-how-to-hub).

## Before You Start

- Inventory is being tracked, and the ledger is being posted. On-hand is summed from ledger movements, so an unmaintained ledger produces an unreliable snapshot.
- Parts you want to see are flagged as stocked. Make-to-order parts not held in inventory are left off by design.
- Safety stock and reorder levels are set where you want shortage flagging to mean something.

## Step 1: Open the Report

Open Reports from the main navigation and click the **Stock on Hand** card. There is no date prompt: the report is a snapshot of the current moment and loads immediately. Rows arrive sorted shortages first, and the total inventory value shows on the subtitle bar.

## Step 2: Read a Part Row

Each row is one stocked part:

- **On-hand quantity**, summed from the inventory ledger.
- **Unit**, **cost per unit**, and **total value**, so the snapshot doubles as a valuation.
- **Safety stock** and **reorder level**, the thresholds that drive shortage flagging.
- **Last transaction** and **days since transaction**, which surface parts that have gone quiet.

## Step 3: Work the Shortage Band

Because the grid sorts shortages first, the parts below their reorder level sit at the top. Read down that band and, for each part, decide whether a purchase or a replenishment run is needed before the day's jobs consume it. This turns the report into a daily shortage worklist rather than a static inventory dump.

## Step 4: Use It as a Daily Check

Run the report each morning. It is instant, and it already ranks the parts that need attention. Combined with the last-transaction column, it lets you catch both parts that are short now and parts that have stopped moving and may surprise you soon.

## Where the Numbers Come From

On-hand is the running sum of every posted receipt and issue in the ledger, not a stored field. Summing the ledger is deliberate: the ledger is the authoritative record of movement, while a stored on-hand value is a cache that can drift out of step. When the cache and the ledger disagree, a consistency check flags it, but this report always shows the ledger sum, so it is the number to trust.

## How to Check It Worked

The report is read-only, so nothing is saved. Confirm it worked by checking a part whose recent movement you know: post a receipt, re-run the report, and the on-hand should rise by that quantity. If it does not, confirm the receipt actually posted to the ledger and that the part is flagged as stocked.

## Common Mistakes

- **Expecting non-stocked parts to appear.** Only stocked parts are listed. A missing make-to-order part is correct behavior, not a gap.
- **Trusting a stored on-hand over the ledger.** The report sums the ledger for a reason. If a stored value looks different, the ledger is the authority.
- **Ignoring a negative on-hand.** A negative quantity is an over-issue to investigate in the transaction history, not a state to leave alone.
- **Setting no reorder levels.** Without thresholds, the shortage sort has nothing to rank against and the daily worklist loses its point.
