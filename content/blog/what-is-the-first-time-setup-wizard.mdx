**The first-time setup wizard is the guided onboarding flow EDGEBIC shows on a fresh installation, walking you through seven ordered steps from an empty database to a schedulable job.** It exists so a new user never has to guess what to configure first. Each step embeds the real editor for that item, so by the completion step you have defined everything a schedule needs and can generate your first one.

[EDGEBIC by User Solutions](/edgebic) launches the wizard automatically on a new installation. This article defines it and walks the seven steps. For the deployment choices behind the very first step, see the sibling term [data source provider](/blog/what-is-a-data-source-provider).

## How It Works

The wizard is a linear, seven-step flow. You move forward only when the current step passes a basic validation, so you cannot skip past something a schedule will need. You can always step back to a completed step to review or adjust it, and the wizard remembers the furthest point you have reached, so going back never loses your progress.

The seven steps, in order:

1. **Data source** picks where the database lives and how to connect, using the same editor you would use later in Settings. Applying a database change here performs an intentional restart, after which the wizard resumes at the next step.
2. **Shift** defines your working hours, for example a day shift running Monday to Friday.
3. **Product** creates something to make.
4. **Work center** creates a machine or cell to make it on.
5. **Routing** defines the sequence of steps that product follows.
6. **Order** creates a real job to schedule.
7. **Completion** shows a summary and offers a jump straight to the scheduler.

Each middle step embeds the same full editor used elsewhere in EDGEBIC, in a simplified wizard mode, so you are entering real data rather than throwaway samples. A short prompt after each step offers to add another of the same item or move on.

## A Concrete Example

Think of the wizard as the setup checklist a good machine ships with: mount it, plug it in, load material, run a test part. You would not skip mounting the machine and expect the test part to work. The wizard enforces that same sensible order for a shop.

Walk a fresh install through it:

| Step | You define | Example |
|---|---|---|
| Data source | Where data lives | Local single-file database (the default) |
| Shift | Working hours | Day shift, Mon-Fri, 08:00 to 16:00 |
| Product | Something to make | Widget A |
| Work center | Where to make it | Mill-1, two machines |
| Routing | The steps | Cut, then Machine |
| Order | A job | 100 of Widget A, due in two weeks |
| Completion | Summary | Button: go to the scheduler |

At the end, that first order schedules against the shift, work center, and routing you just created, proving the whole chain works end to end on a brand-new database.

## How EDGEBIC Uses It

The wizard appears automatically the first time a fresh installation opens, before the main window, and it is the recommended path for any new site. Because each step reuses the real editor, nothing you enter is throwaway: the shift, product, work center, routing, and order you create in the wizard are the ones you keep working with.

On a single workstation you can accept the default local database and move straight through; for a shared, multi-user site you set up the server database right on the first step and let the wizard restart and resume. A brand-new database also arrives with one account already in place, the [bootstrap administrator account](/blog/what-is-a-bootstrap-administrator-account), which is created before anything else and cannot be deleted.
