**When a routing step requires a certification, the machine's free hours mean nothing unless a qualified person has hours left too, and the fastest fix is usually one more certified operator rather than one more machine.** This walkthrough follows a weld cell at Corbin Fabrication in [EDGEBIC by User Solutions](/edgebic) from a puzzling report on Monday to a rescheduled week on Wednesday. It is one of the [worked examples](/blog/edgebic-worked-examples) we publish so the diagnosis is visible rather than described.

The symptom is specific and it fools people for months: jobs queue on a machine that reports half idle.

## Monday, The Symptom That Does Not Add Up

Corbin's weld cell, Weld-1, is two identical machines on a single day shift, 07:00 to 15:00. That is 16 machine hours a day.

Four weld jobs are open this week, 34 hours of weld work in total. At 16 hours a day the backlog is two days of work, and the last job should finish Wednesday afternoon with room to spare.

The schedule says otherwise. The last of the four lands the following Monday and shows up on the Late Jobs report two days past due.

The planner checks the obvious causes first. No holidays that week. No downtime entered. No priority job holding the cell. The work center utilization report puts Weld-1 at 51 percent for the week, which is the number that makes no sense at all: half the cell is idle and the work is still late.

## Monday, The Second Lens

The machine lens is not the only lens.

Open the **Workcenter** tab, then the **Resource Calendar**, and set **Show:** to **Operators**, or to **Both** to see the two side by side. This is the people view: per operator and per skill pool, availability against booked hours over time.

The picture resolves in about ten seconds. The TIG-Weld pool reads 8 hours available a day and 8 hours booked. It is at 100 percent every single day of the week.

Ray Delgado is the only person at Corbin holding a current TIG-Weld certification.

That is the whole story. The weld steps on these routings carry a **Required Skill** of TIG-Weld and an **Operator attention** of 1.0, meaning one operator hour per machine hour: somebody stands at the machine for the whole run. So the cell's real capacity for these jobs is not 16 hours a day, it is 8, and the second machine is unusable for skill-gated weld work no matter how empty it looks.

An unstaffed shift is unusable capacity, and nothing on the machine report says so, because for these steps the machine genuinely was not free.

The concept behind this is in [how operator skills constrain a schedule](/blog/how-operator-skills-constrain-a-schedule).

## Monday, Check the Attention Value Before Blaming It

One check before you go recruiting, because it is the most common misconfiguration in this whole area.

Setup always books one full person. The attention fraction describes only the run phase after setup, and the default value is 0.0, not 1.0. Four values matter:

| Attention | What it means | Effect |
|---|---|---|
| 0.0 | Setup only, then the machine runs itself | The run books nobody |
| 0.5 | One person tends two machines | 8 operator hours buy 16 machine hours |
| 1.0 | Somebody stands at the machine the whole time | One operator hour per machine hour |
| 2.0 | Two person crew | Every machine hour books two operator hours |

Corbin's welding is genuinely hands-on, so 1.0 is honest and stays. This is worth resisting: setting 0.5 to make the schedule fit is borrowing hours from a person who does not have them, and the plan will be wrong on the floor rather than on the screen.

If the welding really were unattended after setup, the correct fix would be the attention value, not a second welder, and the whole problem would evaporate for free. Check before you spend.

## Tuesday, The Cost of Each Option

Three ways to add weld capacity, priced honestly.

**Buy a third machine.** Zero usable hours added. The second machine is already idle half the time because there is nobody to stand at it. This option is not merely expensive, it is ineffective.

**Add a second shift on the cell.** Adds machine hours and needs a certified welder on that shift, which is the same problem shifted eight hours later. The route only works if the person exists.

**Certify a second welder.** Nina Brooks already welds mild steel on the cell and needs the TIG qualification, which is a training day and a test. It takes the TIG-Weld pool from 8 hours a day to 16 and lets both machines run the same job day.

The training day wins on every axis, and it is only visible as an option because the operator lens named the constraint correctly.

## Wednesday, The Configuration

Four small steps, each one saving immediately.

**Add the operator.** On the **Daily Hours** tab, **Operators** inner tab, add Nina with a name and a badge code and leave the status active. Full procedure in [how to add an operator](/blog/how-to-add-an-operator-in-edgebic).

**Certify the skill.** Select Nina, open the **Skills** sub-tab, and add the TIG-Weld certification. Set the **Expires On** date if the certification genuinely expires: an expired certification stops qualifying the person on the next scheduling run, which is far better than discovering it at audit. See [how to certify an operator with an expiry date](/blog/how-to-certify-an-operator-with-an-expiry-date-in-edgebic).

**Roster her.** On the **Roster** sub-tab, add a row for the global Day Shift and tick Monday through Friday. Roster rows attach to global shifts, so one row covers every work center whose calendar derives from that shift. Detail in [how to build a weekly operator roster](/blog/how-to-build-a-weekly-operator-roster-in-edgebic).

**Leave the steps on automatic staffing.** This one is a decision, not a click. If any of the weld steps carry a named operator in the **Operator** field, the pin is hard: that step uses only that person's hours and never falls back to the pool, even when a qualified colleague is free all week. Certifying Nina would change nothing for a step pinned to Ray. Set the pin back to automatic unless the identity of the welder is a genuine customer requirement.

## Wednesday, Reschedule and Read It

Master data does not move a plan. Rerun the four weld jobs.

| | Before | After |
|---|---|---|
| TIG-Weld pool hours per day | 8 | 16 |
| Backlog of 34 weld hours | 4.25 days | 2.2 days |
| Last job finish | Following Monday | Thursday |
| Jobs on Late Jobs report | 1 | 0 |
| Weld-1 machine utilization | 51 percent | 94 percent |

Two jobs now run in parallel, one welder on each machine. The Gantt tooltip on each bar carries its crew line, naming the operator and the hours, and the **Dispatch** tab prints the week grouped by operator and date so the supervisor can hand each person their own list.

The scheduler picks who gets the work by taking whoever has the most free hours that day, and it will split one operation's hours across several qualified people if that is what fits. You do not assign anyone; you make people available and the run staffs them.

## The Line to Read Twice

Weld-1 went from 51 percent to 94 percent machine utilization.

Nothing was added to the machines. The hours were always there. What changed is that they became usable, and the number that had been reassuring the planner all along, 51 percent, was measuring the wrong thing for these steps.

It also means the constraint has moved. Weld-1 is now the tight resource at 94 percent, and the next hour of weld demand costs a real decision rather than a training day. That is normal and healthy: relieving a constraint always promotes the next one, and the useful habit is to go looking for where it landed rather than assuming the problem is solved. The general pattern is in [bottleneck migration and constraint shifting](/blog/bottleneck-migration-constraint-shifting).

## What This Walkthrough Proves

1. **Machine utilization can be reassuring and wrong.** For a skill-gated step, an unstaffed hour is not a free hour.
2. **Read both lenses before spending money.** The operator view of the resource calendar named the constraint in ten seconds.
3. **Check the attention value first.** If the run is genuinely unattended, the fix is a setting rather than a hire.
4. **A pin defeats the whole exercise.** Pinned steps never fall back to the qualified pool.
5. **Nothing moves until you rerun.** Certifications and rosters are master data.
