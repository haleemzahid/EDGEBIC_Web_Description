**To set a scenario priority level in EDGEBIC, open the quote's Scenarios view, select or create a scenario, and set Priority Level (1 to 10) in the Production Settings group, then click Save Changes and Run Simulation.** A higher number makes the simulated job compete more aggressively for capacity. The default is 5, and it affects the scenario simulation only.

A scenario in EDGEBIC by User Solutions is a named what-if variant of a quote's simulation. Priority Level is the lever for testing "what if we treated this as a rush job," biasing how hard the simulated job fights the existing load for capacity. It changes no real job, so it is a safe way to see whether rush treatment would land a tight date before you promise it.

## Before You Start

- **A quote exists and has been simulated once.** Scenarios are children of a quote, and the base simulation is your comparison baseline. See [how to create a what-if scenario](/blog/how-to-create-a-what-if-scenario-in-edgebic).
- **You understand priority reorders, it does not add hours.** If the constraint is full, priority alone will not land the date.
- **You keep a baseline scenario.** A Priority 5 Standard scenario is what you compare the rush test against.
- **You will set real priority separately.** Winning the work means setting a real order priority, which the scenario does not do.

## Step 1: Open the Scenario View

On the **Quote** tab, select the quote and click **Scenarios**. The What-If Scenario Analysis view opens. Select an existing scenario or click **Create New Scenario** and name it after the lever, for example `Treat as rush`.

## Step 2: Find the Production Settings Group

On the **Scenario Parameters** tab, locate the **Production Settings** group. It holds the levers that shape how the simulated job schedules.

## Step 3: Set the Priority Level

Set **Priority Level (1-10)**:

| Priority Level | Simulates |
|---|---|
| **8 to 10** | A rush job that competes hard for capacity against existing load |
| **5** | The default, balanced competition |
| **1 to 4** | A low-urgency job that yields to other work |

## Step 4: Save and Simulate

Click **Save Changes**, then **Run Simulation**. Read the **Simulation Results**: **Estimated Start Date**, **Estimated End Date**, **Lead Time**, **Total Hours**, and **Estimated Cost**. Each run overwrites this scenario's stored results, and nothing touches the shop plan.

## What Changes When You Save

| Action | What changes | What does NOT change |
|---|---|---|
| **Save Changes** | The scenario's stored parameters | The quote, the schedule, any real job |
| **Run Simulation** | The scenario's stored dates, hours, and cost | The production schedule; no real priority moves |

## How to Check It Worked

1. Confirm **Priority Level** shows the value you set.
2. Click **Run Simulation** and note the **Estimated End Date**.
3. Open the **Comparison Analysis** tab, tick this scenario and a Priority 5 baseline, and read the Lead Time chart. A meaningful priority effect shows as a shorter bar; little movement means the constraint, not sequencing, is the limit.
4. Confirm no real job changed: open your live schedule and verify job priorities are untouched.

## Common Mistakes

**Expecting priority to create capacity.** Priority reorders the queue; it does not add hours. When the constraint is full, test a capacity override or extra shift instead.

**Confusing it with a real order priority.** The scenario value biases the simulation only. Set a real manufacturing order priority separately if you win the work.

**Forgetting to save before simulating.** Save Changes stores the setting, and Run Simulation applies it. A scenario edited but not simulated cannot be applied to the quote.

**Reading only lead time.** A rush that wins by starving other work is worth knowing about. Check the Utilization comparison tab too.
